# 웹 화면만 Vercel에 올리기 — 회의 (2026-10-30)

- 참석: 리드(진행), 배포·인프라, 보안·개인정보, 백엔드·프론트엔드. 모두 에이전트예요. 코드는 고치지 않았어요.

## 한눈에

1. **API는 Vercel rewrites로 서버에 넘겨요(3명 모두).**
   - 브라우저 기준 출처가 하나라서 상대 주소 `/api`, `__Host-` 쿠키, CSP `connect-src 'self'`, OIDC 콜백이 그대로 돌아요. 개발 프록시(`apps/web/vite.config.ts`)와 같은 구조예요.
   - 다른 출처를 직접 부르는 방식(CORS)은 10~12개 파일을 고쳐야 해요(2~3일). `vercel.app`은 다른 사이트로 취급돼서 쿠키가 서드파티 차단에 걸려요. 화면 주소(`/r/<토큰>`)는 그래도 Vercel을 지나가요. 그래서 채택하지 않았어요.
2. **서버가 따로 떠 있어야 해요.**
   - 웹만 올리면 "지금 서버에 연결할 수 없어요" 화면만 보여요(`App.tsx`). 로그인 화면까지도 가지 못해요.
   - 서버는 서버리스에 못 올려요(상시 실행, 한 시간마다 보관 잡, 메모리 세션). 같은 Docker 이미지를 상시 컨테이너 한 대에 띄워요(Fly.io·Railway·Render·Cloud Run min-instances=1 등).
3. **Vercel은 시연 한정이에요(보안 금지선, 3명 동의).**
   - Vercel이 TLS를 끝내서 묻기 원문·문의 본문·세션 쿠키·`/r/<토큰>`·OIDC `code`가 Vercel(국외 업체)을 지나가고, 경로·쿼리·IP가 우리가 가릴 수 없는 로그에 남아요. ADR-10과 10/29 관문 합의(쿼리·본문 빼고 7일)를 지킬 수 없어요.
   - 그래서 실제 IdP·실제 자료·파일럿·운영은 Vercel 뒤에 두지 않아요. 파일럿은 11/16 호스팅 결정 뒤 10/29 합의안(이미지 하나 + 사내 관문)으로 돌아가요.
4. **10/29 합의 세 곳에 예외가 생겨요.** "CDN 안 씀", "시연은 사내망·IAP 뒤"(쟁점 5), "관문이 로그를 가림". 사용자 결정 변경으로 남겨요.

## 1. 쟁점 판정

| 쟁점 | 판정 | 근거 |
|---|---|---|
| API 연결 | rewrites 프록시 | 코드 변경 거의 없음. CORS는 쿠키·CSP·OIDC 돌아오기·MCP issuer를 다 나눠야 해요 |
| 넘길 경로 | `/api/*` 하나. 단 `/api/ops/*`는 빼요(`/api/((?!ops/).*)`) | `/health`는 부하 분산기만 봐요. `/mcp`·`/.well-known`·`/oauth/*`는 MCP 단계 전엔 닫아요(시연은 MCP 늘 꺼요). 운영 설정은 사내망만인데 Vercel은 사내망을 가르지 못해요 |
| 화면 주소 | `/`, `/oauth/consent`, `/r/:token`만 index.html. 모든 주소 받기(`/(.*)`) 금지 | `core/web-files.ts` `SCREEN_PATHS`와 같게. 모두 받으면 없는 `/api`에 200 HTML이 가서 `me()`가 `{}`를 로그인으로 잘못 읽어요 |
| 판(DESK_BUILD) | 웹과 서버를 같은 커밋·같은 형식(40자)으로 함께 배포. 서버 먼저, Vercel 나중 | 판이 다르면 새 버전 띠가 뜨고 회의실 채팅 바로 실행이 막혀요(`rooms/routes.ts`). Vercel 빌드에 값을 안 넣으면 웹이 `dev`가 돼서 띠 없이 바로 실행만 영영 막혀요 |
| 접근 통제 | Trusted IPs(회사 출구) + 비밀번호, 프리뷰도 같은 보호. 서버는 Vercel만 받게 | 비밀번호 하나로는 15명 명단을 보장 못 해요. Trusted IPs는 상위 요금제로 알아요. 서버가 공개라서 직접 붙으면 Vercel 보호를 건너뛰어요 |
| TRUST_PROXY | 시연은 `none`. 시연 접속지는 법정 기록으로 쓰지 않는다고 적어요 | Vercel 출구는 넓고 바뀌는 대역이라 `/24` 검사에 걸려요. 검사를 풀지 않아요. 믿으려면 고정 출구 IP(Enterprise)나 비밀 머리(개발 필요)가 있어야 해요 |

## 3. 결정이 필요한 것

### 사용자
- 시연 서버를 둘 곳(Fly.io·Railway·Render·Cloud Run 중). 비용과 지역(국내 리전 여부)을 같이 봐요.
- 쟁점 5(사내망·IAP)를 "Trusted IPs + 비밀번호"로 바꿀지. Trusted IPs가 요금제에 없으면 비밀번호만으로 갈지, 시연을 늦출지.
- Vercel을 시연 한정으로 ADR-01에 남길지.

### 회사
- 정보보안팀: Vercel을 처리 위탁 업체로 승인할지, 시연 접속기록 취급(B8과 함께)
- 개인정보 보호책임자: 국외 이전·위탁 고지
- IT 인프라: Vercel 요금제, 커스텀 도메인

## 4. 남은 위험

- 웹과 서버 배포가 끝나는 사이에 잠깐 띠가 뜨고 바로 실행이 막혀요. 잦으면 판 비교를 "계약 판"(shared 규칙 해시)으로 바꾸는 안을 다시 봐요. 이 안은 D1 안전장치가 약해져서 지금은 하지 않아요.
- Vercel이 바뀌면 옛 탭이 지워진 `/assets` 조각을 불러 404가 나요(10/29 쟁점 1 ⑤). Skew Protection이 없으면 새로 고침 안내로 버텨요.
- Vercel이 주는 502·504는 우리 응답이 아니라서 "고치는 중이에요" 문구로 보여요. 관문 `maintenance.html` 역할은 없어요.
