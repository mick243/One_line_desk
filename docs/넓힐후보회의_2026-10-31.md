# 넓힐 후보 회의(2026-10-31)

- 참석: 기획자, 디자이너, 개발자(테크 리드) · 진행: 리드
- 안건: `docs/차별화회의_2026-10-31.md` 6절의 넓힐 후보 다섯 가지를 어떻게 만들지, 넣으면 무엇을 잃는지
  - ① 신규 입사자 온보딩
  - ② IT 오류 문장 → FAQ 원문 단계 → 티켓 초안
  - ③ MCP 담당 찾기 공개
  - ④ 부서 간 문의 처리 통계
  - ⑤ 여러 시스템 허브
- 방식: 1라운드에서 역할마다 따로 안을 냈어요. 2라운드에서 서로의 안에 반론했어요. 원칙과 부딪히는 넷은 사용자가 정했어요.
- 결과 결정: `docs/ADR.md` ADR-25, ADR-14 개정안(제안)

## 1. 먼저 찾은 기존 구멍

분장표 어댑터가 늘 `mock: true`였어요(`modules/navi/index.ts`). 그래서 두 가지가 틀렸어요.

- 실제 분장표를 S5로 올려도 "시연 데이터로 돌아가는 중이에요" 띠에 "업무 분장표(가상 분장표)"가 남았어요.
- 시연 배포에서 MCP "모두 모의 자료" 판정(`allMockData`)이 계속 참이었어요. 그래서 시연 클라이언트가 허용 목록에 남았어요.

지금은 MCP에 담당 도구가 없어서 새는 자료는 없었어요. 하지만 ③을 열기 전에 반드시 고쳐야 해서, 세 역할 모두 "지금 따로 고친다"로 모였어요.

## 3. 사용자 결정(10/31)

1. ② 티켓 초안: 복사 버튼 없이 앱 안 문의만 보내요. 배포 준비 회의의 "복사 버튼 안 만듦"을 그대로 지켜요.
2. ④ 통계: 받은 부서 주간 건수만 세고, 7일 보관해요. ADR-21 예외는 없어요.
3. ① 온보딩: 이번 묶음에 같이 만들어요.
4. ③ MCP 담당 찾기: 이번엔 ADR-14 개정안 문서만 써요.

## 4. 넣으면서 생기는 트레이드오프

| 기능 | 얻는 것 | 잃는 것·문제 |
|---|---|---|
| 분장표 출처 | 띠·MCP 판정이 실제와 맞아요 | 마이그레이션 하나. 시연 배포에서 실제 분장표를 올리면 MCP 시연 클라이언트가 막혀요(의도). 서버가 여러 대면 메모리 값이 어긋날 수 있어요 |
| ② IT 붙여넣기 | 원문 저장 없이 FAQ 단계 → 앱 안 문의 | IT FAQ 원문이 없으면 가상 FAQ뿐이에요(IT팀에 11/30까지 받아야 해요). 바깥 티켓 시스템에는 손으로 다시 써요. FAQ가 낡으면 단계가 틀려요 |
| ① 첫 2주 할 일 | 분장표 주인이 관리하니 개정일이 따라가요 | 진행이 안 남아 매번 처음부터 훑어요. 칸이 비면 화면도 비어요. 분장표 양식이 바뀌어 주인 부서 안내가 필요해요 |
| ④ 주간 셈 | 처리 전 지워짐(성공 지표 3)을 셀 수 있어요 | 보이는 건 한 주뿐이에요. 파일럿 규모에선 대부분 10건이 안 돼 접혀요. 지우기 경로를 바꿨어요(트랜잭션) |
| ③ 미룸 | 꺼진 코드·다시 허락 흐름을 관리하지 않아요 | 경쟁사(플로우 MCP 쓰기 19개) 앞 차별 거리가 늦어져요 |
| ⑤ 미룸 | 연동마다 생기는 장애 지점이 없어요 | 링크 허브는 창구 링크 수준에 머물러요 |
