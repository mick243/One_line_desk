# 회사 한 벌 추가 절차(ADR-23)

회사마다 앱을 한 벌씩 따로 띄워요. 서버·PostgreSQL·IdP·비밀 값·주소가 회사마다 따로라서, 한 회사 앱은 다른 회사가 있는지 몰라요. 이 문서는 운영팀이 새 회사를 더할 때 따라 하는 순서예요.

## 지키는 것

- 회사는 무작위 ID(`t-xxxxxx`)로만 불러요. 호스팅 앱·폴더·DB 이름에 회사 이름을 쓰지 않아요.
- 회사 ID와 실제 회사 이름의 대응, 회사 목록, `tenant.env`는 저장소 밖 비공개 폴더(또는 비밀 저장소)에만 둬요. 이 저장소에 커밋하지 않아요. 도구가 저장소 안 폴더를 거절해요.
- 회사 고르기·회사 찾기 화면, 공용 첫 화면을 만들지 않아요. 회사에는 그 회사 주소만 알려 줘요.
- 주소는 회사 자기 도메인 아래 전용 하위 도메인 루트예요(예: `desk.회사도메인`). 인증서도 그 도메인으로 받아요. 호스팅 기본 주소(`*.fly.dev`)는 회사에 알리지 않아요.
- 모든 회사가 같은 커밋을 받아요.

## 회사에서 받을 것

| 받을 것 | 쓰는 곳 |
|---|---|
| 전용 하위 도메인과 DNS 연결 | `PUBLIC_BASE_URL` |
| IdP(OIDC) 주소, 웹 클라이언트·직원 명단 클라이언트 비밀 값, 리디렉트 등록(`https://<주소>/api/auth/oidc/callback`) | `DESK_IDP_*` |
| 관문(프록시) 주소. 관문이 없으면 `none` | `TRUST_PROXY` |
| 처리 위탁 계약·보관 기간·국외 이전 동의, AI 무보관 계약 여부 | 계약 문서. AI는 확인 전까지 `DESK_AI_PROVIDER=fake` |

## 순서

1. **틀 만들기**: `npm run tenant -- new --dir <비공개 폴더>`. 회사 ID와 비밀 값 넷이 새로 생기고, `<비공개 폴더>/<ID>/tenant.env`와 `fly.toml`이 만들어져요. ID와 회사 이름의 대응을 운영팀 비공개 문서에 적어요.
2. **DB 만들기**: 이 회사 전용 PostgreSQL 17을 만들어요. 다른 회사와 같은 DB·같은 서버의 다른 스키마로 나누지 않아요.
   - 계정 둘: 소유자 계정(표 주인, `DESK_MIGRATE_DATABASE_URL` — 배포 release_command의 `db:migrate`만 써요)과 앱 계정(`DATABASE_URL`, 로그인만 되는 역할). 두 주소가 같으면 검사에서 멈춰요(11/11 QA Q5).
   - 표와 앱 계정 권한은 값을 채우고 검사를 지난 뒤(4번) `db-init`이 한 번에 넣어요(5번). 앱 계정은 표 만들기·지우기·TRUNCATE를 못 하고, 접속기록은 넣기·읽기·1년 지난 줄 지우기만 해요. 앞으로 소유자가 만드는 표에도 같은 권한이 붙어요.
   - 시점 복구(PITR)를 켜요. 보관 기간은 ADR-21 백업 줄 결정을 따라요(장애런북 3-1절).
3. **값 채우기**: `tenant.env`의 `__FILL_ME__`를 채워요.
4. **검사**: `npm run tenant -- check --dir <비공개 폴더> --id <ID>`. 빠진 값과 운영 설정 검사에 걸리는 것을 이름만 알려 줘요(값은 찍지 않아요). 다 지나야 다음으로 가요.
5. **DB 준비(첫 배포 전 한 번)**: `npm run tenant -- db-init --dir <비공개 폴더> --id <ID>`. 소유자 주소로 마이그레이션 → 앱 계정 권한(`db/roles/app-grants.sql`) → 앱 계정으로 권한 확인 순서로 돌아요. 권한 SQL은 표가 있어야 돌아가고, 배포(7번)는 마이그레이션 → 배포 → 연기 시험을 한 번에 돌려서 권한을 배포 뒤에 주면 앱 계정이 권한 없이 떠 연기 시험에서 걸려요. 이 컴퓨터에서 회사 DB에 닿아야 해요(사설망이면 `flyctl proxy` 등으로 열어 둬요). 손으로 하려면 `npm run db:migrate`(소유자 주소) 뒤 `psql "<소유자 주소>" -v app_role=<앱 계정> -f db/roles/app-grants.sql`이에요.
6. **앱 만들기**: `flyctl apps create desk-<ID>`.
7. **배포**: 커밋한 상태에서 `npm run tenant -- deploy --dir <비공개 폴더> --id <ID>`. 앱 계정 권한 확인(읽기만, 어긋나면 멈추고 `db-init`을 안내해요) → 비밀 값 넣기 → 마이그레이션(release command) → 배포 → 연기 시험(`scripts/smoke.mjs`) 순서로 돌아요. DB에 닿지 못하는 곳에서 이미 확인했다면 `--no-db-check`를 붙여요.
8. **주소 연결**: 회사 도메인을 앱에 붙이고 인증서를 받아요(`flyctl certs add <주소> -a desk-<ID>`).
9. **전달**: 회사 담당자에게 그 회사 주소 하나만 알려 줘요.

## 켜기 전에(회사가 할 일)

- 같은 팀 일정·오늘 우리 팀(운영 스위치 `teamSchedule`, 출시 기본 끔): 같은 부서 사람의 오늘 휴가(하루/오전/오후)·자리비움이 홈에 수로, 누르면 이름으로 보여요. 30인 이상 사업장은 근로자참여법상 "근로자 감시 설비" 협의 대상이 될 수 있어서, 켜기 전에 노사협의회 협의와 사내 고지(개인정보 처리방침 포함)를 회사가 먼저 해요(ADR-18 11/25 보강).

## 운영 자료 넣기(파일럿 전, 11/11 QA Q8)

운영은 가상 자료를 넣지 않아서 처음에는 회의실·탕비실 구매 카탈로그·공지 사본이 비어 있어요. 운영자가 회사 자료를 저장소 밖 파일로 만들어 `npm run ops:data -- rooms <파일.csv>`(머리 줄 `id,name,floor,capacity,equipment,facilities`), `catalog <파일.csv>`(`id,name,unitPrice,packUnit,aliases`), `notices <파일.json>`(허용 게시판 공지 배열 `[{ id, board, title, postedOn, url, body }]`)으로 먼저 미리 보고, 거절한 줄이 없으면 같은 명령 끝에 `--apply`를 붙여 반영해요. 거절한 줄이 하나라도 있으면 반영하지 않아요. 반영하면 감사 로그에 내용 없이 한 줄(모듈·`ops-import`·`rows:N`)만 남고, 파일에 없는 회의실·품목은 지우지 않고 그대로 둬요. 공지는 새 공지마다 알림 대상 제안과 총무 확인 알림이 생겨서, 새 공지 알림 자동 보내기(`noticeAutoSend`)가 켜져 있으면 막혀요. 본문은 DB에 남지 않아요(그래서 이 길로 넣은 공지는 찾기만 되고 "원문 한 줄" 인용은 안 돼요). 운영 환경에서 앱 계정(`DATABASE_URL`)으로 돌리고, 마이그레이션이 남아 있으면 명령이 멈춰요.

## 업데이트(모든 회사)

배포 창 전에 회사마다 관리형 DB 스냅숏을 하나 찍어요(장애런북 3-1절). 그다음 커밋한 상태에서 `npm run tenant -- deploy --dir <비공개 폴더>`. 폴더 안 모든 회사를 같은 커밋으로 하나씩 배포하고, 하나라도 연기 시험에 실패하면 멈춰요. 실패한 회사는 `flyctl releases -a desk-<ID>`로 앞 판을 찾아 되돌려요. 새 마이그레이션이 든 배포를 되돌려도 앞 판이 떠요(장애런북 3절, `db-newer-migrations` 경고).

## 그만 쓸 때

회사와 정한 보관 기간에 따라 자료를 넘기거나 지운 뒤 앱과 DB를 지워요. 접속기록(1년)은 지우기 전에 회사에 넘길지 정해요(ADR-20).
