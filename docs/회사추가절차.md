# 회사 한 벌 추가 절차(ADR-23)

회사마다 앱을 한 벌씩 따로 띄워요. 서버·PostgreSQL·IdP·비밀 값·주소가 회사마다 따로라서, 한 회사 앱은 다른 회사가 있는지 몰라요. 이 문서는 운영팀이 새 회사를 더할 때 따라 하는 순서예요.

## 지키는 것

- 회사는 무작위 ID(`t-xxxxxx`)로만 불러요. 호스팅 앱·폴더·DB 이름에 회사 이름을 쓰지 않아요.
- 회사 ID와 실제 회사 이름의 대응, 회사 목록, `tenant.env`는 저장소 밖 비공개 폴더(또는 비밀 저장소)에만 둬요. 이 저장소에 커밋하지 않아요. 도구가 저장소 안 폴더를 거절해요.
- 회사 고르기·회사 찾기 화면, 공용 첫 화면을 만들지 않아요. 회사에는 그 회사 주소만 알려 줘요.
- 주소는 회사 자기 도메인 아래 전용 하위 도메인 루트예요(예: `desk.회사도메인`). 인증서도 그 도메인으로 받아요. 호스팅 기본 주소(`*.fly.dev`)는 회사에 알리지 않아요.
- 모든 회사가 같은 커밋을 받아요.

## 회사에서 받을 것

| 받을 것 | 쓰는 곳 |
|---|---|
| 전용 하위 도메인과 DNS 연결 | `PUBLIC_BASE_URL` |
| IdP(OIDC) 주소, 웹 클라이언트·직원 명단 클라이언트 비밀 값, 리디렉트 등록(`https://<주소>/api/auth/oidc/callback`) | `DESK_IDP_*` |
| 관문(프록시) 주소. 관문이 없으면 `none` | `TRUST_PROXY` |
| 처리 위탁 계약·보관 기간·국외 이전 동의, AI 무보관 계약 여부 | 계약 문서. AI는 확인 전까지 `DESK_AI_PROVIDER=fake` |

## 순서

1. **틀 만들기**: `npm run tenant -- new --dir <비공개 폴더>`. 회사 ID와 비밀 값 넷이 새로 생기고, `<비공개 폴더>/<ID>/tenant.env`와 `fly.toml`이 만들어져요. ID와 회사 이름의 대응을 운영팀 비공개 문서에 적어요.
2. **DB 만들기**: 이 회사 전용 PostgreSQL 17을 만들어요(앱 계정과 소유자 계정을 나눠요). 다른 회사와 같은 DB·같은 서버의 다른 스키마로 나누지 않아요.
3. **값 채우기**: `tenant.env`의 `__FILL_ME__`를 채워요.
4. **검사**: `npm run tenant -- check --dir <비공개 폴더> --id <ID>`. 빠진 값과 운영 설정 검사에 걸리는 것을 이름만 알려 줘요(값은 찍지 않아요). 다 지나야 다음으로 가요.
5. **앱 만들기**: `flyctl apps create desk-<ID>`.
6. **배포**: 커밋한 상태에서 `npm run tenant -- deploy --dir <비공개 폴더> --id <ID>`. 비밀 값 넣기 → 마이그레이션(release command) → 배포 → 연기 시험(`scripts/smoke.mjs`) 순서로 돌아요.
7. **주소 연결**: 회사 도메인을 앱에 붙이고 인증서를 받아요(`flyctl certs add <주소> -a desk-<ID>`).
8. **전달**: 회사 담당자에게 그 회사 주소 하나만 알려 줘요.

## 업데이트(모든 회사)

커밋한 상태에서 `npm run tenant -- deploy --dir <비공개 폴더>`. 폴더 안 모든 회사를 같은 커밋으로 하나씩 배포하고, 하나라도 연기 시험에 실패하면 멈춰요. 실패한 회사는 `flyctl releases -a desk-<ID>`로 앞 판을 찾아 되돌려요.

## 그만 쓸 때

회사와 정한 보관 기간에 따라 자료를 넘기거나 지운 뒤 앱과 DB를 지워요. 접속기록(1년)은 지우기 전에 회사에 넘길지 정해요(ADR-20).
