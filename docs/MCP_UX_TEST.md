# MCP UX 시험 — Claude Code·Codex 세션에서 쓰기

- 날짜: 2026-10-26 · 대상: 읽기 전용 MCP(`/mcp`, 도구 `rooms_find_free`·`notices_search`) · 서버: 로컬 개발(main `fde2494`, 가상 자료)
- 물음: 직원이 Claude Code나 Codex 세션에서 한 줄 데스크 MCP를 쓸 때 불편한 곳이 있나요?

## 한 줄 결론

**연결이 가장 큰 벽이에요. 연결된 뒤 도구 쓰기는 대체로 매끄러워요.**
- 지금 서버는 동적 등록(DCR)도 CIMD도 없어요. 비밀 값이 있는 클라이언트만 받고, 리디렉트 주소가 정확히 같아야 해요.
- 그래서 `claude mcp add --transport http desk <주소>`처럼 기본 방식으로 붙이면 Claude Code는 바로 실패해요. Codex도 문서상 같은 이유로 실패해요.
- 연결된 뒤에는 Claude가 자연어 조건을 도구 입력으로 정확히 바꾸고, 예약은 못 한다는 것도 정직하게 알려요.
- 연결 뒤 걸리는 곳은 넷이에요.
  - 담당 안내 질문을 받을 도구가 없어요.
  - 운영자가 MCP를 끄면 인증 오류처럼 보여요.
  - 예약 링크가 너무 길어요.
  - 방 정보가 모자라서 Claude가 어느 방이 나은지 고르지 못해요.

## 어떻게 시험했나

| 무엇 | 방법 | 범위 |
|---|---|---|
| 연결(인가) | 실제 Claude Code 2.1.309를 토큰 없이 붙여 오류를 기록했어요(`claude -p --mcp-config`, `--debug-file`). 우리 서버의 보호 자원 메타데이터·인가 서버 메타데이터를 직접 받아 보고, Claude Code·Codex 방식의 리디렉트 주소로 인가를 시작해 봤어요 | Claude Code 실기 + Codex 문서 대조 |
| 도구 쓰기 | 연결 단계만 건너뛰려고 시험용 헤더 도우미(`headersHelper`)를 썼어요. 도우미가 가상 직원 하늘로 인가·동의·토큰을 받아요. 그 상태에서 `claude -p`에 한국어 질문 9개를 넣었어요. 도구 호출·입력·결과·최종 답을 `stream-json`으로 기록했어요 | Claude Code 실기 |
| Codex | 이 PC에 Codex CLI가 없어서 실기 시험은 못 했어요. 공식 문서(아래 출처)의 OAuth·리디렉트 동작을 우리 서버 응답과 맞대 봤어요 | 문서 대조 |

## 불편한 점 (심각도 순)

| # | 심각도 | 무엇 | 근거 | 고칠 방향 |
|---|---|---|---|---|
| U1 | 높음 | **기본 방식으로는 연결 자체가 안 돼요.** Claude Code는 "Incompatible auth server: does not support dynamic client registration"으로 실패해요. Codex는 클라이언트 ID가 없으면 CIMD → DCR 순으로 시도하는데 둘 다 없어요 | Claude Code 디버그 기록. 인가 서버 메타데이터에 `registration_endpoint`가 없고, `token_endpoint_auth_methods_supported`가 `client_secret_basic`·`client_secret_post`뿐이에요 | ① CLI용으로 **공개 클라이언트**(PKCE, 비밀 없음, `token_endpoint_auth_method: none`)를 받아요. ② 또는 **CIMD**를 지원해요. 두 클라이언트 모두 자동으로 써요. 허용 목록은 CIMD 주소로 관리해요 |
| U2 | 높음 | **CLI 리디렉트 주소가 등록된 주소와 안 맞아요.** 등록은 정확히 일치해야 하고, 지금 등록된 건 claude.ai 콜백 하나뿐이에요. Claude Code는 `http://localhost:<포트>/callback`을 쓰고 포트는 기본이 무작위예요. Codex는 `http://127.0.0.1:<포트>/callback`을 써요(우리가 `iss` 응답을 지원한다고 알려서 고정 경로). 두 방식 모두 지금 그대로면 `/oauth/consent?error=invalid-request`가 돼요 | 인가 시도 2건이 모두 302 → invalid-request였어요 | 루프백 주소(`localhost`·`127.0.0.1`·`[::1]`)는 **포트와 상관없이** 경로만 맞추면 받아요(RFC 8252 §7.3). 그 전까지는 포트를 고정하는 안내가 필요해요(`--callback-port`, Codex `oauth.callback_port`) |
| U3 | 높음 | **CLI마다 클라이언트 비밀을 나눠 줘야 해요.** 비밀 값이 있는 클라이언트만 받아서 직원 모두가 같은 비밀을 가져야 해요. Codex는 그 비밀을 `config.toml`에 평문으로 저장해요. 게다가 운영자가 클라이언트를 등록할 경로가 없어요(REVIEW 남은 일) | 토큰 엔드포인트 코드, Codex 문서 | U1의 공개 클라이언트나 CIMD로 비밀 배포를 없애요. 운영자 등록 화면(보안팀 승인 칸 포함)을 만들어요 |
| U4 | 높음 | **운영자가 MCP를 끄면 "인증 오류"로 보여요.** `/mcp`가 403 `mcp-off`를 돌려줘요. Claude Code는 401·403을 인증 문제로 봐요. 그래서 "토큰을 새로 받고 `/mcp`로 다시 연결하라"고 잘못 안내해요. OAuth 사용자라면 다시 로그인하라는 요청을 되풀이해 보게 돼요 | 시나리오 s9: `AUTH_HEADER_REJECTED`, 잘못된 해결 방법 안내 | 꺼짐은 인증과 나눠요. 200 + 빈 도구 목록 + 서버 안내문에 "운영자가 잠시 껐어요"를 담거나, 도구 호출에 `isError` 안내를 돌려줘요. 또는 503 + `Retry-After`로 답해요 |
| U5 | 높음 | **담당 안내 질문을 받을 도구가 없어서 Claude가 추측해요.** "법인카드 잃어버렸는데 어디에 연락해?"에 공지만 세 번 찾다가 "보통 재무팀이나 회계팀"이라고 근거 없이 답했어요. 한 줄 데스크가 가장 잘하는 질문인데 Claude에서는 근거 없는 답이 나와요 | 시나리오 s5 | 서버 안내문(`instructions`)에 "담당 부서 질문은 한 줄 데스크 앱(주소)에서 물어보세요"를 넣어요. 읽기 전용 담당 안내 도구는 ADR-14(도구 둘) 변경이라 기획 결정이 필요해요 |
| U6 | 중간 | **두 번째 세션·기기를 연결하면 첫 연결이 끊겨요.** 승인이 "직원 × 클라이언트"마다 하나라, 다시 동의하면 이전 접근·갱신 토큰이 바로 무효가 돼요. 같은 클라이언트를 노트북·데스크톱에서 쓰면 서로 끊어요 | 병렬 시험에서 4개 중 3개가 401 `invalid_token`이었어요. 코드 `repo.upsertGrant`(on conflict → grant_id 교체) | 승인을 기기(갱신 토큰 계열)별로 두고, S6에는 앱 이름 아래 기기 수를 보여요 |
| U7 | 중간 | **예약 링크가 450자쯤이라 답이 지저분해요.** 서명한 제안 토큰을 그대로 주소에 넣어서 터미널에서 줄이 길게 접혀요. 토큰을 풀면 가명 ID·조건도 보여요(REVIEW L3) | 시나리오 s1·s2·s3·s6 | 서버에 저장하는 짧은 ID(`/r/abc123`)나 짧은 봉인 토큰으로 바꿔요 |
| U8 | 중간 | **방 정보가 모자라 Claude가 어느 방이 나은지 못 골라요.** 결과에 수용 인원·갖춘 장비가 없어요. "제일 좋은 데로"라고 하면 "품질로 고른 건 아니에요", "대회의실 5C는 이름으로 보면 클 수 있어요"라고 짐작해요 | 시나리오 s3 | 후보마다 `capacity`·`equipment`를 넣어요. 동의 화면의 "방·층·시간·인원·장비"와 같은 범위예요. 정렬 기준(인원에 맞는 방 먼저 등)도 도구 설명에 적어요 |

## 잘 된 점

- **조건 바꾸기가 정확해요:** "내일 오후 3시", "다음 주 화요일 10시부터 2시간", "화상회의", "5층"을 모두 맞는 입력으로 바꿨어요(`2026-11-03`, `minutes: 120`, `equipment: ["화상회의"]`, `floor: "5층"`). 목록에 없는 "빔프로젝터"는 "화면"으로 바꾸고, 바꿨다고 밝혔어요.
- **읽기 전용 안내가 통해요:** "바로 예약까지 해 줘"에도 "예약은 하지 못했어요 … 링크를 열어 앱 확인 시트에서"라고 답했어요. 서버 안내문 두 문장만으로 충분했어요.
- **시간 기준이 보여요:** "10:54 기준", "그사이 다른 사람이 예약했을 수 있어요"를 스스로 덧붙였어요.
- **도구 지연은 작아요:** 질문 하나가 11~29초 걸렸는데, 대부분 모델 시간이에요. Claude Code는 도구 설명을 필요할 때 불러오고(ToolSearch), 도구 둘의 설명은 짧아서 부담이 없어요.

## Codex에서 (문서 대조, 실기 시험 못 함)

- **기본 연결:** 클라이언트 ID가 없으면 CIMD를 먼저 시도하고, 안 되면 DCR을 시도해요. 우리 서버는 둘 다 없어서 실패할 거예요(U1).
- **미리 등록한 클라이언트:** `codex mcp login <이름> --oauth-client-id … --oauth-client-secret …`로 연결할 수 있어요. 비밀은 `~/.codex/config.toml`에 평문으로 저장돼요(U3).
- **리디렉트 주소:** 우리 서버가 `authorization_response_iss_parameter_supported: true`를 알려서 Codex는 `http://127.0.0.1:<포트>/callback`을 써요. 포트는 기본이 실행 중인 임의 포트예요. `oauth.callback_port`나 `mcp_oauth_callback_port`로 고정할 수 있어요. Claude Code는 `localhost`를 쓰니 지금 방식이면 두 주소를 따로 등록해야 해요(U2).
- **토큰 직접 넣기:** `bearer_token_env_var`나 `http_headers_helper`도 있어요. 하지만 접근 토큰이 150초라 사람이 손으로 쓰기는 어려워요.
- **실기 시험:** 해 보려면 Codex CLI를 설치하고 OpenAI 계정으로 로그인해야 해요.

## 고치는 순서 제안

1. **U4·U5(작은 수정):** 꺼짐을 인증 오류와 나누고, 서버 안내문에 담당 질문은 앱으로 보내라는 안내를 넣어요. 둘 다 서버 몇 줄이에요.
2. **U1·U2·U3(연결):** 공개 클라이언트 + 루프백 포트 자유 허용, 또는 CIMD. 어느 쪽으로 갈지는 보안팀 질문과 함께 정해야 해요(ADR-15 변경).
3. **U6~U9(쓰기 편함):** 기기별 승인, 짧은 링크, 방 수용 인원·장비, 빈 결과 이유.
