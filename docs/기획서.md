# 기획서: 한 줄 데스크

> 회의실 잡기, 탕비실 채우기, 누구한테 물을지. 한 줄 쓰면 확인 카드로 돌려줘요.

- 상태: 초안 · 마지막 수정: 2026-10-23
- 근거: `회의/00_브리프.md`, 기존 제품 조사 `회의/00_기존제품_A_해외.md`(아래 "A"), `회의/00_기존제품_B_국내.md`(아래 "B"), 회의 결정 `회의/03_결정.md`(D1~D13)
- 함께 보는 문서: `docs/PRD.md`(기능·완료 기준), `docs/화면설계.md`(디자이너)

## 배경과 문제

**지금 겪는 일**
- 직원: 일이 생기면 "이거 어느 메뉴, 어느 부서 일이지?"부터 찾아요. 법인카드 분실, 명함, 간식 신청처럼 가끔 하는 일이 특히 그래요. 회의실은 그룹웨어 화면에서 조건을 하나씩 골라 잡아요. 탕비실은 말할 곳이 마땅치 않고, 같은 상품을 사람마다 다른 이름으로 말해요("제로콜라", "코카콜라 제로 355").
- 총무: 회의실·비품·"누구한테 물어봐요" 문의를 반복해서 받아요(가정, 사용자 확인 3). 탕비실 요청을 손으로 모아 합치고, 예산 안에서 층마다 나눈 근거를 설명하기 어려워요.
- 담당 부서: 업무 분장표가 낡아도 고칠 신호가 없어요. 엉뚱한 부서로 온 문의를 다시 돌려보내요.

**기존 제품으로 안 풀리는 곳**
- 회의실과 공지는 이미 풀려 있어요. 국내 그룹웨어 다섯 곳(네이버웍스·카카오워크·U+웍스·두레이·하이웍스)이 화면 예약을 해요(B C1). 카카오워크AI·네이버웍스 AI 스튜디오·다우오피스 AI가 공지·규정 질의를 해요(B C3).
  - 남는 건 "AI가 예약안을 내고 사람이 확인 버튼을 누르는 흐름" 하나예요. 국내 시판 제품에는 없어요(B 4절 5).
- 탕비실은 비어 있어요. 자유 문장 합치기 + 1인 1표 + 층별 최소 몫 공정 주문안 + 근거 설명을 하는 제품은 국내외 모두 없어요(A 4절 1·2, B 4절 1·2).
- 담당 안내는 반쯤 비어 있어요. 기존 제품은 요청을 받은 뒤 큐로 보내요(A 4절 4). 분장표로 "담당·지금 할 일·처리 기간" 카드를 근거와 함께 주는 기능은 없어요. 다만 그룹웨어 AI 에이전트 설정으로 흉내 낼 위험은 있어요(B 4절 3).
- 세 영역을 한 창에서 하는 제품도 없어요(A 4절 7, B 4절 6). 하지만 없다는 사실이 필요하다는 근거는 아니에요.

**기존 제품 판정**

| 영역 | 판정 | 이유 |
|---|---|---|
| 회의실 조회·예약 + 공지 | Configure Existing Tools 쪽 | 그룹웨어 화면 예약·공지와 그룹웨어 AI가 이미 해요. 남는 건 "AI 제안 → 사람 확인 → 확정 순간 재확인" 흐름뿐이에요 |
| 같이 채워요 | Build a Custom Product | 합치기·1인 1표·층별 공정 주문안·근거는 어디에도 없어요 |
| 담당자 내비 | 작게 Build (ServiceNow·JSM을 쓰는 회사면 Configure) | 분장표 카드와 근거 강제가 없어요. 그룹웨어 AI로 흉내 낼 위험은 있어요 |
| 전체 | 좁게 Build a Custom Product | 핵심 가치는 같이 채워요와 안전 장치(쓰기 분리·원문 비보관·근거 강제)예요. Just Use AI는 해당 없어요(사내한정 데이터와 여럿이 같이 쓰는 상태가 필요해요) |

## 목표와 성공 지표

**2주 목표**
1. 세 흐름을 시연에서 끝까지 보여 줘요: 담당 카드, 회의실 확인 예약, 탕비실 요청 → 합치기 → 주문안.
2. 보안 바닥 시험을 통과해요: 원문 비보관, 공개 판 유출 차단, 쓰기 경계, 등급 3 차단.
3. 정확도 측정표를 남겨요(자료 30~50건, 브리프 기준). 무보관 계약 전이면 가상(등급 0) 자료로 재고 "가상"이라고 적어요.
4. 파일럿(층 1~2개, 가정)을 시작할 준비를 끝내요. 회사 명의 무보관 계약이 확인되기 전에는 실제 직원 파일럿을 시작하지 않아요.
5. 읽기 전용 MCP 흐름을 모의 데이터로 시연해요: 동의 → 조회 → 앱 링크 → 앱에서 예약, 연결 끊기, 퇴사 차단.

## 대상 사용자와 사용 장면

| 역할 | 하는 일 | 주로 쓰는 화면 |
|---|---|---|
| 직원 (사내 불특정 다수) | 묻기, 회의실 예약, 탕비실 요청·+1, 내 것 확인 | S1 묻기, S2 결과 시트, S3 같이 채워요 판, S6 내 것 |
| 총무 | 합치기 확정·되돌리기, 예산·층 최소 몫·표 상한 입력, 주문안 확정·내보내기 | S4 총무 운영 |
| 분장표 주인 (담당 부서) | 자기 부서 행에 쌓인 "틀렸어요" 기록 묶음을 보고 행을 직접 고쳐 저장 | S5 분장표 수정 제안함 |
| 운영자 (개발자 본인) | 내용 없는 감사 로그, 10명 이상 묶음 통계, 오류·AI 비용만 봐요. 끄기 스위치를 바꾸고, 보안팀 승인 목록에 오른 MCP 클라이언트를 등록해요. 질문 원문·투표자는 못 봐요 | 운영 설정·통계(화면 번호 없음) |

**하루 장면**
1. **오전, 입사 2주 차 직원**: 묻기 탭에 "법인카드 잃어버렸어요"를 써요. 담당 카드가 떠요(담당 팀·창구, 지금 할 일, 처리 기간, 분장표 근거 행). 담당이 틀렸으면 "틀렸어요" → [다른 담당이에요]를 눌러요. 그 기록은 분장표 주인의 S5에 쌓여요. 질문 원문은 가지 않아요.
2. **오전, 회의를 잡는 직원**: "내일 3시 6명 화면 있는 방"을 써요. 조건 칩과 후보가 "현황 HH:MM 기준"과 함께 떠요. 확인하는 사이에 다른 예약이 들어오면 "막힘" 카드와 대안(최대 2개)이 떠요.
3. **점심 뒤 탕비실**: "제로콜라 또 넣어 주세요"를 써요. 미리보기에 "'코카콜라 제로'라는 이름으로 우리 층 사람들에게 보여요. 내 이름은 안 보여요"가 떠요. 이미 같은 품목이 있으면 +1만 해요.
4. **주문 마감 날, 총무**: 쌓인 합치기 제안을 확정해요. 예산과 층별 최소 몫을 넣으면 주문안이 품목마다 이유 칩·근거 문장과 함께 나와요. 고쳐서 확정하고 파일로 내보내 기존 절차대로 주문해요. 확정하면 주기가 닫히고 새 주기가 열려요. 표를 준 직원은 S6 "내 요청"에서 "주문에 들어감"을 봐요(알림은 다음 2주).
5. **회의 안건을 정리하던 직원(승인 AI 클라이언트 사용)**: claude.ai 조직 커넥터에서 "내일 3시 6명 빈 회의실 있어?"라고 물어요. 빈 방 후보와 "한 줄 데스크에서 예약하기" 링크가 와요. 링크를 열면 앱이 다시 조회한 후보가 뜨고, [이 방으로 예약] → [예약하기]로 한 번 확인해요.

## 콘셉트와 범위

**할 일이 정해진 안내 데스크**
- "무엇이든 하는 AI 비서"가 아니에요. 할 수 있는 일이 정해진 창구예요. 이름과 화면 어디에도 "AI 비서"를 앞세우지 않아요.
- 앞문은 담당자 내비예요. 모르는 일, 못 하는 일은 담당 안내로 넘겨서 입력창이 막다른 길이 되지 않게 해요.
- 화면은 아래 탭 셋이에요: **묻기**(나만 보여요) / **같이 채워요**(우리 층 모두에게 보여요) / **내 것**. 공개·비공개를 화면 구조로 갈라요(D4).

**비대칭 범위**

| 깊이 | 기능 | 이유 |
|---|---|---|
| 깊게 | F3 같이 채워요 | 빈칸이 확인된 유일한 기능이에요 |
| 중간 | F1 담당 카드 | 빈칸이지만 그룹웨어 AI로 흉내 낼 위험이 있어요 |
| 얇게 | F1 공지 찾기(제목·원문 링크), F2 회의실 | 그룹웨어가 이미 해요. 확인 흐름만 우리 몫이에요 |
| 얇게 | MCP 읽기 채널(F1·F2 공통) | 새 일이 아니라 F1·F2 읽기 기능에 다는 문이에요. 깊이는 인가·허용 목록에서 나와요 |

**끄기 스위치와 반대 결론 판정 규칙(D1)**
- 모듈마다 스위치를 둬요: `켬 / 링크만 / 끔`. 운영 설정이라 운영자만 바꿔요. 링크만은 "이 일은 그룹웨어에서 해요" 링크 카드, 끔은 그 종류를 후보에서 빼고 담당 안내로 보내요.
- 회사가 그룹웨어 AI를 이미 켰거나 회의실 실제 연결이 안 되면, 회의실·공지를 "링크만"으로 낮춰요. 담당 카드와 같이 채워요는 남아요.
- 파일럿에서 회의실이 거의 안 쓰이면, 다음 2주에 회의실을 링크 카드로 바꿔요.
- 기능마다 운영 주인이 다르면 "같이 채워요 단독" 모드로 가요. navi·notices·rooms를 모두 끄고, 묻기 탭을 숨기고, 같이 채워요 탭이 첫 화면이 돼요.

**핵심 기능**
- **F1 묻고 근거 카드 받기**: 분장표 행을 근거로 한 담당 카드, 물을 때만 찾는 공지 카드(제목·게시일·원문 링크), 근거가 없으면 "여기로 물어보세요"(총무 창구) 카드, "틀렸어요" 기록 → 분장표 주인이 S5에서 보고 분장표 파일을 고쳐 다시 올림.
- **F2 회의실 찾고 확인 예약**: 조건 → 후보 최대 3장 → 확인 시트 → 확정 순간 재확인 → 예약·취소. 쓰는 곳은 모의 장부예요.
- **F3 같이 채워요**: 공개 요청·+1·합치기 제안·총무 확정·층별 최소 몫 주문안과 근거.
- **MCP 읽기 채널(F1·F2 공통)**: `rooms_find_free`·`notices_search` 두 도구, 쓰기 없음, 예약은 앱 링크에서 한 번 확인. F4로 세지 않아요.

**이번에 안 하는 것(요약, 자세한 건 PRD "이번에 안 하는 것")**
- IT 오류 캡처 OCR·FAQ 해결 단계·티켓 초안(다음 2주 1순위). 이번엔 IT 질문을 담당 카드(IT 창구 + 기존 헬프데스크 링크)로 끝내요.
- MCP 쓰기 도구·동적 클라이언트 등록·허용 목록 밖 클라이언트·공지 본문/요약 제공, 식단·셔틀, 공지 할 일 뽑기·필독 알림, 장애 신고 묶기, 반복 예약, 실제 주문·ITSM 연동, 홈 "새 공지" 카드, 담당 카드의 관련 공지 링크.
- 다음 2주로 미룬 것(MCP 시간 마련, M6): 공지 인용 요약, S5 화면 안 행 고치기, 같이 채워요 알림과 "알림 링크로 들어온 횟수" 지표, 판 실시간 밀어 주기(이번엔 새로고침).
- 이견 기록: 기획자는 IT 붙여넣기 흐름을 F1에 넣자고 했어요(D3에서 2:1로 뺐어요).

**겹치는 주제와 경계**
- 공지 ↔ 마감 레이더: 우리는 **물을 때만** 공지를 찾아 제목과 원문 링크를 보여 줘요(MCP도 같아요). 할 일·대상·마감 뽑기, 맞춤 목록, 필독 알림은 마감 레이더 몫이에요.
- 담당자 내비 IT ↔ 나만 안 돼요?: 우리는 한 사람의 "어디에 물어봐요"만 해요. 여러 사람 신고를 모으거나 묶지 않아요. 질문 원문을 남기지 않으니 묶을 재료도 없어요.

**MCP 결정: 2주 안에 읽기 전용 MCP를 열어요(D11을 M1~M7로 바꿈)**
- 앱 형태는 모듈형 모놀리스 웹앱 그대로예요. 공통 바닥 위에 rooms·notices·pantry·navi 모듈이 있고, 같은 읽기 기능을 MCP 도구 둘로도 열어요.
  - `rooms_find_free`: 빈 방 후보 최대 3개(방·층·시간·맞은 조건), "한 줄 데스크에서 예약하기" 링크, 조회 시각. 예약자·회의 제목·방별 일정은 없어요.
  - `notices_search`: 허용 게시판 공지의 제목·게시일·원문 링크만 줘요. 본문·요약은 없어요. MCP 경로에서는 LLM을 부르지 않아요.
- 이유: 사용자가 사용자 확인 1번에 "2주 안에 읽기 전용 MCP도 넣어 줘"라고 답했어요. 원래 요청("회사생활 MCP에서")을 지키는 길이에요.
- 지키는 선
  - 쓰기 도구는 열지 않아요. 예약은 링크를 열어 앱에서 [이 방으로 예약] → [예약하기]로 한 번 확인해요. 링크를 누른 건 확인이 아니에요.
  - 우리 서버가 인가 서버를 맡고, 로그인은 사내 IdP로 중개해요. 토큰 대상(`aud`)을 검사하고, 접근 토큰은 짧게, 갱신 때마다 재직을 다시 확인해요. 퇴사하면 늦어도 10분 안에 끊겨요.
- 허용 정책(두 겹)
  - 기술: 미리 등록한 기밀 클라이언트만 받아요. 동적 등록은 꺼요. 2주 시험 클라이언트는 claude.ai 조직 커넥터 하나예요.
  - 정책: 보안팀 승인 목록에 오른 클라이언트만 등록해요. 클라이언트 쪽 무보관 계약이 확인되기 전에는 목록이 비어 있어서, 실제 데이터로는 켜지 않고 시연은 모의(등급 0) 데이터로만 해요.
- 예전 "열지 않음"의 이유 셋은 위험으로 남아요: 인가 구현 부담(https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), 등급 1 결과가 외부 클라이언트 모델로 감, 확인을 클라이언트에 맡길 위험. 앞의 둘은 위험 표로 받고, 마지막은 쓰기 도구를 열지 않아 막아요.
- 면접 가치: 30선에서 회사생활 MCP는 "API 연동뿐"(면접 매력 2점)이었고 "사용자별 인가(OAuth)를 깊게 파야" 한다는 지적을 받았어요. 이제 퇴사자 토큰, 아무 AI 앱이나 붙이기, AI가 예약까지 해 버리기를 구조로 막는다고 답할 수 있어요. 각각 갱신 때 재직 재확인, 허용 목록, 쓰기 없음과 앱 확인이에요.

**반대 결론의 최선 논거**
> "그룹웨어 AI를 이미 쓰는 회사라면 회의실·공지·규정 질의는 설정으로 끝나요. 2주는 같이 채워요 하나에 쓰는 게 나아요."

- 우리 답: D1의 끄기 스위치와 판정 규칙으로 받아요. 회의실·공지는 언제든 링크 카드로 낮출 수 있고, F3는 혼자 설 수 있게 나눠 만들어요.
