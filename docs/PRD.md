# PRD — 한 줄 데스크

## 개요

- 상태: 초안
- 한 줄 설명: 회의실 잡기, 탕비실 채우기, 누구한테 물을지. 한 줄 쓰면 확인 카드로 돌려줘요.
- 마지막 수정: 2026-10-26(화면 구조: 앞문 묻기 없이 홈 + 기능별 페이지, ADR-02 개정 · `docs/화면설계.md` "10/26 화면 구조"). 아래 기능 설명의 "묻기"·S1·S2는 이제 각 기능 페이지의 입력 칸과 결과예요. 회의실 페이지에는 "모든 회의실"(방 카드 → 설비·하루 일정·이 시간 예약)도 있어요(ADR-06 개정). 담당 찾기에서 담당 팀(분장표 주인 부서)에 문의·사유를 보내고, 받는 팀과 보낸 사람은 앱 안 알림을 받아요(ADR-16, 메일·메신저 알림은 아직이에요).
- 근거 문서: `docs/기획서.md`, `회의/03_결정.md`(D1~D13), `회의/05_수정지시.md`(R1~R18), `회의/08_MCP_결정.md`(M1~M7), 기존 제품 조사 `회의/00_기존제품_A_해외.md`·`00_기존제품_B_국내.md`
- 대상 사용자: 직원(사내 불특정 다수), 총무, 분장표 주인(담당 부서), 운영자(개발자 본인). 회사가 승인한 AI 클라이언트를 쓰는 직원은 MCP로 회의실 조회·공지 찾기도 해요.
- 해결할 문제: 직원은 "이거 어디서 해요?"를 물을 곳이 없어요. 분장표가 낡아도 고칠 신호가 없어요.
  - 탕비실 요청은 이름이 제각각이라 표가 흩어지고, 총무는 층별로 나눈 근거를 대기 어려워요.
  - 회의실·공지는 그룹웨어가 이미 해요. 그래서 얇게 두고 끌 수 있게 해요(D1).

## 핵심 기능

| ID | 기능 | 설명 | 완료 기준 |
|---|---|---|---|
| F1 | 묻고 근거 카드 받기 | 묻기 탭에 한 줄 쓰면 종류를 나눠요. 담당 질문엔 분장표 행 원문으로 담당 카드를, 공지 질문엔 공지 제목·게시일·원문 링크를 줘요. 근거가 없으면 "여기로 물어보세요"(총무 창구) 카드로 가요. "틀렸어요" 기록은 분장표 주인의 S5에 쌓여요 | 근거 행 없는 담당 카드 0건, 질문 원문 저장 0건, 주인이 분장표를 다시 올리기 전 반영 0건 |
| F2 | 회의실 찾고 확인 예약 | 말로 쓴 조건으로 빈 회의실 후보를 최대 3장 보여 줘요. 사람이 한 번 확인해야 예약되고, 확정 순간 다시 확인해요. 쓰는 곳은 모의 장부예요 | 확인되지 않은 plan으로 생긴 예약 0건, 동시 확정 시 한 명만 성공, 남의 예약자 이름 노출 0건 |
| F3 | 같이 채워요 | 층별 공개 요청판에 품목을 올리고 +1을 눌러요. AI가 같은 상품 합치기를 제안하고 총무가 확정해요. 층별 최소 몫을 지키는 주문안을 품목마다 근거와 함께 짜요 | 한 사람이 한 묶음에 2표 이상 세진 경우 0건, 합치기를 모두 풀면 카드별 표가 투표 행에서 다시 센 값과 같음, 예산 초과 0건, 채울 수 있는 입력에서 최소 몫을 못 받은 층 0건, 못 채운 층은 모두 경고 |

- 읽기 전용 MCP는 F4로 세지 않아요. F1·F2의 읽기 기능에 문을 하나 더 다는 일이라 아래 "MCP 읽기 채널(F1·F2 공통)" 절에 요구와 완료 기준을 모아요(M1).

### F1 묻고 근거 카드 받기

세부 요구
1. 입력창은 묻기 탭(S1)에만 있어요. 머리에 "나만 보여요", 안내 문구는 "이거 어디서 해요? 한 줄로 물어보세요"예요. 예시 문장 칩 3개는 누르면 입력창을 채우기만 하고, 보내기는 사람이 눌러요.
2. 보내기 전 공통 검사: 키·토큰 형식이면 보내기를 잠가요. 이메일·IP는 브라우저에서 `[이메일]`·`[IP]`로 바꿔 보내요(풀기 없음). 주민번호·비밀번호·건강 정보처럼 보이면 막고 이유를 보여 줘요. 무엇을 바꿨는지는 입력 칸 바로 아래 가림 줄로 보여 줘요.
3. 라우팅은 공통 검사 → 규칙 → LLM 한 번 순서예요. LLM은 `{종류, 슬롯, 애매함}`을 돌려줘요. 종류는 담당(`navi`)·공지(`notices`)·회의실(`rooms`)·탕비실(`pantry`)·모름(`unknown`)이에요. 확신이 낮으면 종류 칩 최대 3개와 "다른 거예요"로 되물어요. 모름과 "다른 거예요"는 담당 안내(분장표 검색, 읽기 전용)로 가요.
4. 담당 카드: LLM은 후보 중 분장표 행 ID 하나나 `없음`만 골라요. 화면은 그 행 원문(담당 팀·창구, 지금 할 일, 처리 기간, 근거 행·개정일)을 그려요. 사람 이름은 안 보여 줘요. 처리 기간이 비면 "분장표에 없음"이라고 적어요.
5. `없음`이면 담당 카드를 만들지 않고 "여기로 물어보세요"(총무 창구) 카드를 보여 줘요. 못 찾은 건수는 묻기 감사 로그의 결과 칸("못 찾음")으로만 세요. 운영자가 묶음 통계로 총무에게 전해요.
6. IT 질문은 IT 창구와 기존 헬프데스크 링크가 담긴 담당 카드로 끝내요. 해결 단계는 보여 주지 않아요.
7. 공지는 물을 때만 허용 게시판 사본에서 찾아요(규칙·색인 검색). 카드에는 제목·게시일·원문 링크만 보여 줘요. 인용 요약은 다음 2주예요(D13 ①을 처음부터 적용, M6).
8. "틀렸어요" 선택지는 [다른 담당이에요](후보 행 최대 3개에서 고르기) [목록에 없어요] [안내 내용이 바뀌었어요] [종류가 달라요](칩 바꾸기)예요.
   - 남기는 것은 (예측 종류, 고친 종류, 예측 행, 고른 행, 이유 코드, 시각)뿐이에요. 사용자 ID·가명 ID는 남기지 않아요. 기록은 묻기와 다른 피드백 경로로 보내고, 자유 문장 칸은 없어요. 칩을 바꾸면 페이지 메모리의 같은 문장으로 다시 불러요.
9. S5에서 분장표 주인이 자기 부서 행에 쌓인 기록 묶음을 봐요(다른 행이 골라짐 · 목록에 없음 · 내용이 바뀜 · 종류가 다름).
   - 이번 2주 S5는 기록 묶음 목록과 분장표 파일 다시 올리기만 있어요(D13 ②를 처음부터 적용, M6). 주인이 파일의 자기 부서 행(창구·할 일·처리 기간·"다른 말")을 고쳐 확인 시트로 올려야만 반영돼요. 기록이 분장표를 자동으로 바꾸지는 않아요. 화면 안에서 행을 고치는 기능은 다음 2주예요.
10. 탕비실 의도면 F3 공개 미리보기로 넘겨요.
11. 같은 공지 찾기 기능을 MCP 도구 `notices_search`로도 열어요("MCP 읽기 채널" 절).

시험 가능한 완료 기준
- 분장표·공지에 없는 질문을 섞은 시험에서 근거 행 없는 담당 카드 0건, 원문 링크 없는 공지 카드 0건. 공지 카드에 본문·요약 문장 0건.
- 사람 이름 칸이 든 시험 분장표를 가져온 뒤, 그 이름 값이 DB·응답·화면에서 0건.
- 질문에 넣은 카나리 문자열이 DB·로그·오류 보고·프록시 로그·브라우저 저장소·URL에서 0건.
- 키·토큰 시험 문자열 전부에서 보내기가 잠겨요. 서버가 받은 본문에 이메일·IP 원형 0건.
- 주인이 파일을 다시 올리기 전 분장표 반영 0건. 다른 부서 행을 바꾼 파일과 주인이 아닌 사람의 올리기는 거부돼요.
- "틀렸어요" 기록에 사용자 ID·가명 ID 0건. 묻기 감사 로그에 분장표 행 ID·공지 ID·슬롯 값 0건.
- 정답 단 질문 30~50건으로 담당 정답률과 라우터 경계 문장 결과를 표로 남겨요. 무보관 계약 전이면 가상 자료로 재고 "가상"이라고 적어요. 목표치는 1주 차 기준선 뒤에 정해요.

### F2 회의실 찾고 확인 예약

세부 요구
1. 문장에서 날짜·시작 시각·길이·인원·장비·층을 뽑아 조건 칩으로 보여 줘요. 칩은 고칠 수 있어요. 빠진 값은 되물어요. 길이 기본값은 운영 설정이고 운영자만 바꿔요.
2. 후보는 최대 3장이에요. "현황 HH:MM 기준"과 맞은 조건(고른 이유)을 붙여요.
3. 처음부터 빈 방이 없으면 "안내" 카드로 "그 시간엔 빈 방이 없어요"와 가까운 시간 대안을 최대 2개 보여 줘요. 대안도 없으면 "대안 없음"과 조건 고치기를 보여 줘요.
4. 후보 카드에는 서버가 서명한 짧은 수명의 제안 토큰(슬롯 값)만 붙어요. `/ask`는 아무것도 저장하지 않아요.
   - [이 방으로 예약]을 누르면 rooms 쓰기 경로가 plan(방·시간·요청자·조건 슬롯·만료 시각)을 만들고 확인 시트를 열어요. 확인 시트의 [예약하기]는 plan_id만 보내고, 누르면 바로 잠겨요. 사람의 확인은 이 한 번이에요.
5. 실행 순간 서버가 세션·권한을 다시 검사해요. plan이 만료됐으면 같은 조건 슬롯으로 다시 찾아 새 후보를 보여 주고 "시간이 지나 다시 찾았어요"라고 적어요. 예약은 DB 겹침 제약으로 쓰고, 멱등 키는 plan_id예요.
6. "막힘" 카드는 실행 순간 재검사에서 막혔을 때만 써요. "확인하는 사이에 다른 예약이 들어왔어요"와 대안 최대 2개를 보여 주고, 조건 칩은 그대로 둬요.
7. 결과 카드에 "HH:MM에 다시 확인하고 예약했어요"와 취소를 넣어요. 취소도 확인 시트를 거쳐요. 내 예약은 S1 카드와 S6에 모여요.
8. 하루 안의 한 시간 구간을 내 이름으로 한 건씩 예약해요. 반복·여러 날·대리 예약과 초대 발송은 없어요.
9. 남의 예약은 "예약됨"만 보여 줘요. 어댑터 출력 타입에는 예약자 이름·회의 제목 칸이 없어요.
10. 스위치: rooms가 "링크만"이면 "이 일은 그룹웨어에서 해요" 링크 카드가 떠요. "회의실 쓰기"를 끄면 후보 카드 주 버튼이 "그룹웨어에서 예약하기" 링크로 바뀌어요. 파일럿에서는 실제 연결 전까지 쓰기를 꺼요.
11. 같은 빈 방 찾기를 MCP 도구 `rooms_find_free`로도 열어요. MCP 링크로 들어와도 예약은 이 절의 확인 한 번을 거쳐요("MCP 읽기 채널" 절).

시험 가능한 완료 기준
- 모든 예약 행의 plan_id가 사용자가 확인한 plan을 가리켜요(DB 검사). plan 없이, 남의 plan_id로, 만료된 plan으로 실행해도 예약 0건.
- 같은 방·시간을 두 사람이 동시에 확정하면 한 명만 성공해요. 다른 한 명은 막힘 카드와 대안 최대 2개(없으면 "대안 없음")를 받아요.
- 같은 plan_id를 두 번 보내도 예약 1건. 응답 본문·화면에 남의 예약자 이름·회의 제목 0건.
- 시연 시나리오 통과: 조건 부족 되묻기, 빈 방 없음 안내와 대안, 만료 뒤 다시 찾기, 취소, 스위치(링크만·쓰기 끔).

### F3 같이 채워요

세부 요구
1. S3 판은 층별이에요. 요청 쓰기 칸 머리에 "우리 층 모두에게 보여요"를 둬요. 요청 쓰기 칸에도 F1과 같은 공통 검사를 해요. 투표는 내 층에서만 해요. 품목은 표 많은 순, 같으면 최근 순으로 보여 줘요.
2. 게시는 공개 미리보기 카드 자체가 확인이에요. 사람의 확인은 이 한 번이에요.
   - 묻기에서 오면 제안 토큰에 AI가 뽑은 품목 이름이 들어 있어요. 사용자가 이름을 고치고 [올리기]를 누르면, 토큰과 확정된 이름으로 plan 만들기와 실행을 한 번에 해요. [올리지 않기]면 아무것도 남지 않아요.
   - 판에는 **품목 이름만** 올라가요. 입력 원문은 저장하지 않아요. 문구: "'○○'라는 이름으로 우리 층 사람들에게 보여요. 내 이름은 안 보여요." [올리기] / [올리지 않기], 기본 선택 없음.
3. 실행 직전 서버가 다시 검사해요(등급 3·전화번호·이메일·사람 이름 패턴). 알레르기 같은 건강 정보는 막아요. 비슷한 품목이 이미 있으면 새 글 대신 [여기에 +1] 카드를 보여 줘요.
4. 판에 담당 질문을 쓰면 "이건 담당 안내가 맞아 보여요"와 [묻기로 옮기기]를 보여 줘요. 글은 앱 메모리로만 넘겨요(URL·브라우저 저장소 안 씀).
5. 표는 품목(묶음)마다 1인 1표예요. 올리면 내 표 1개가 자동으로 붙어요.
   - 상한은 "열린 묶음 중 내 표가 있는 묶음 수"예요. 지난 주기에서 넘어온 표와 자동 1표도 들어가요. 값은 총무가 정해요. +1이나 게시를 누르는 순간에만 검사하고, 상한이 차면 게시도 막아요.
   - 합치기가 풀려 상한을 넘으면 "합치기가 풀려 상한을 넘었어요. 새 표는 거둔 뒤에 줄 수 있어요"를 보여 줘요. 요청 횟수 제한도 둬요(값은 운영 설정).
   - 누가 표를 줬는지는 앱 화면·API 어디에도 안 보여요(총무 포함).
6. AI가 합치기·카탈로그 매칭을 제안해요. 게시 순간 같은 층 열린 품목과 비교하고, 총무 화면을 열 때 한 번 더 모아요. 제안은 이미 있는 같은 층 요청만 가리킬 수 있어요.
7. 확정 전에는 판에 "같은 상품 같아요" 표시만 보여서 +1로 이끌어요. 이때 표는 합치지 않아요.
8. 합치기 확정·되돌리기는 **총무만** S4에서 해요. [합치기]·[되돌리기]는 확인 시트를 거치고, [따로 두기]는 바로 실행해요. (이견 기록: 기획자는 "그 층 직원 누구나"를 냈고, D8에서 2:1로 총무로 정했어요.)
9. 표 세기: 묶음 표는 묶음 안 서로 다른 사람 수예요. 표는 원래 요청 카드의 투표 행에 붙어 있어요. 합친 뒤 새로 누른 표는 대표 카드에 붙어요. 합친 뒤 표를 거두면 그 사람이 묶음 안에 가진 표를 모두 거둬요.
10. 동시성: 표를 누를 때는 합치기 버전이 오르지 않아요. 합치기 버전은 묶음 구성(합치기·되돌리기)에만 붙어요.
    - 충돌은 다른 총무가 같은 품목을 먼저 바꿨을 때만 나요("다른 총무가 먼저 이 품목을 바꿨어요. 새로 불러왔어요"). 직원 판은 몇 초마다 새로고침해서 바뀐 묶음과 표 수를 보여 줘요(실시간 밀어 주기는 다음 2주, M6).
11. 주문안(S4): 총무가 예산과 층별 최소 몫 금액을 넣어요(처음엔 같은 금액). 수량은 기본 한 묶음 단위예요.
    - 짜는 법(D8 1단계 보정): 층마다 최소 몫을 먼저 채워요. 묶음을 넣기 전에 "넣어도 이 층과 뒤 층의 최소 몫을 남은 묶음으로 끝까지 채울 수 있는지"를 정확히 계산해서, 안 되면 건너뛰어요. 그다음 나머지를 표 대비 값 순으로 채워요. 모든 층을 채울 수 없으면 층 번호 순으로 채울 수 있는 층부터 채워요.
    - 예산이 최소 몫 합보다 작으면 주문안은 만들되 경고를 띄우고 확정을 잠가요. 총무가 예산이나 최소 몫을 고치면 풀려요.
    - 어떤 층의 요청 금액이 최소 몫보다 작으면 그 층은 있는 만큼만 담아요. "요청이 모자라 최소 몫을 못 채웠어요" 경고를 붙이고, 확정은 잠그지 않아요.
12. 품목 줄마다 이유 코드 칩(층 최소 몫 / 표 대비 값 / 예산 초과로 뺌 / 카탈로그에 없음)과 한 문장 설명을 붙여요. LLM에는 줄 ID·품목 이름·층·표 수·금액·이유 코드·순위만 보내요(투표자 정보 없음). 설명 속 숫자가 데이터와 다르면 틀 문장으로 바꿔요.
13. 총무가 줄을 빼거나 바꾸면 검사기를 다시 돌려요. 고친 줄은 설명을 틀 문장으로 바꾸고 "총무가 고침" 라벨을 붙여요(이유 코드 칩은 그대로).
    - 예산을 넘으면 확정을 잠가요. 고쳐서 최소 몫에 못 미치면 경고만 띄워요. 확정하면 파일로 내보내고, 실제 주문은 총무가 기존 절차로 해요.
14. 주기: 주문안을 확정하면 주기가 닫히고 새 주기가 열려요. 확정 시트 문구는 "주문에 들어간 품목의 표가 닫혀요. 나머지는 다음 주기로 넘어가요."예요. "주기 마감"은 총무가 S4에서 적는 표시용 글자예요.
15. 알림은 다음 2주예요(M6). 이번엔 확정 결과를 S6 "내 요청" 상태(주문에 들어감 · 다음으로 넘어감)로만 보여 줘요. 다음 2주 알림 대상은 주문에 들어간 묶음에 표를 준 사람 모두(올린 사람 포함)이고, 링크엔 카드 ID만 넣어요(R12).

시험 가능한 완료 기준
- 묻기 경로(`/ask`)로 판 쓰기를 시도하면 실패해요(경로·DB 권한 시험). 묻기에 넣은 카나리 문자열이 판·DB에서 0건.
- 판에 올라간 글자와 미리보기에서 사용자가 확정한 글자가 다른 경우 0건.
- 투표·거두기·합치기·풀기를 무작위 병렬로 섞은 시험에서 두 불변식이 지켜져요.
  - ① 묶음 표 = 서로 다른 사람 수
  - ② 합치기를 모두 풀면 카드별 표가 투표 행에서 다시 센 값과 같음
- 상한을 넘는 +1은 거부돼요. +1을 동시에 연타해도 상한을 넘지 않아요.
- 총무가 아닌 역할의 합치기 확정·되돌리기·주문안 확정과 다른 층 투표는 모두 거부돼요.
- 주문안 검사기(총무가 고치기 전 주문안 기준): 예산 초과 0건. 예산이 최소 몫 합 이상이고, 그 층 요청 금액이 최소 몫 이상이고, 정수 계획이 "채울 수 있음"이라고 한 입력에서 최소 몫을 못 받은 층 0건(묶음 단위 때문에 어떤 배정으로도 못 맞추는 입력이 있어요). 무작위 입력 800개를 정수 계획과 비교하는 시험이 매번 확인하고, 하나라도 나오면 실패예요.
  - 못 채운 층에는 모두 경고가 붙어 있어요. 근거 숫자가 다른 줄 0건(다르면 틀 문장으로 바뀌어요).
- 건강 정보 입력 차단 시험을 통과해요. 같은 입력으로 주문안과 정수 계획(highs-js)을 비교해 "채울 수 있음"인데 못 받은 층 0건을 확인하고, 표 합 차이는 기록해요.

### MCP 읽기 채널(F1·F2 공통)

세부 요구
1. 도구는 읽기 둘뿐이에요. 쓰기 도구는 MCP에 없어요. MCP 경로에서 우리 서버는 LLM을 부르지 않고, 규칙·색인으로만 찾아요.
   - `rooms_find_free`: 입력은 날짜·시작·길이·인원·장비·층이에요. 출력은 빈 방 후보 최대 3개(방·층·시간·맞은 조건), "한 줄 데스크에서 예약하기" 링크, 조회 시각이에요. 예약자·회의 제목·방별 일정은 없어요.
   - `notices_search`: 입력은 검색어예요. 출력은 허용 게시판 공지의 제목·게시일·원문 링크만이에요. 본문·요약은 없어요.
2. 앱 확인 링크에는 서버가 서명한 짧은 수명의 제안 토큰(조건 슬롯·사용자·만료)만 넣어요. MCP 경로는 감사 로그 말고는 DB에 쓰지 않아요.
   - 링크를 열면 로그인한 뒤 토큰 주인과 로그인한 사람이 같은지 검사해요(남의 링크는 안 열려요). 같으면 S2가 열리고, 머리에 "Claude에서 가져온 후보예요"와 앱이 지금 다시 조회한 카드가 나와요.
   - **링크를 누른 건 확인이 아니에요.** [이 방으로 예약] → 확인 시트 [예약하기]가 유일한 확인이에요(R2). 그사이 방이 찼으면 R5 안내 카드와 대안을, 만료됐으면 같은 조건으로 다시 찾은 후보를 보여 줘요. 회의실 쓰기가 꺼져 있으면 링크는 "그룹웨어에서 예약하기"예요.
3. 인가: 우리 서버가 MCP 인가 서버를 맡고, 로그인은 사내 IdP로 중개해요. 보호 자원 메타데이터를 내고, 접근 토큰의 대상(`aud`)이 우리 MCP 주소인지 검사해요. 미리 등록한 기밀 클라이언트만 받고, 동적 등록은 꺼요.
   - 접근 토큰은 짧게 살고, 갱신할 때마다 재직을 다시 확인해요. 퇴사하면 늦어도 10분 안에 끊겨요. [끊기]와 "모든 기기 로그아웃"은 그 사람의 MCP 승인(갱신 토큰)을 바로 폐기해요.
4. 허용 클라이언트 정책은 두 겹이에요.
   - 기술: 등록된 클라이언트 ID와 비밀 키를 가진 조직만 붙어요. 2주 시험 클라이언트는 claude.ai 조직 커넥터 하나예요(비밀은 조직 소유자만 넣어요). Claude Code·Copilot Studio는 이번에 빼요.
   - 정책: 그 조직이 회사 명의 무보관 조건인지는 서버가 알 수 없어요. 보안팀 승인 목록에 오른 클라이언트만 운영자가 등록해요. 클라이언트 쪽 무보관 계약이 확인되기 전에는 허용 목록이 비어 있어서 실제 데이터로는 MCP를 켜지 않아요. 시연은 모의 회의실 장부와 가상 공지(등급 0)로만 해요.
5. 연결 동의는 사내 IdP 로그인 뒤 S6 위에 우리 서버가 띄우는 동의 시트예요. 앱 이름, 읽는 것, 못 하는 것(예약·취소·게시), "찾은 결과는 그 앱의 AI 모델로 보내져요", 끊는 곳을 보여 줘요. 버튼 둘은 무게가 같고 기본 선택이 없어요. 허용 목록 밖 앱이면 "회사가 허락하지 않은 앱이라 연결할 수 없어요"만 나와요.
6. S6 "연결된 AI 앱" 칸: 앱 이름, 연결한 날, [끊기](확인 시트)를 둬요. "마지막 사용"은 넣지 않아요. [끊기] 확인 시트에는 "이미 그 앱으로 간 결과는 그쪽 기록에 남을 수 있어요"라고 적어요.
7. 감사 로그는 가명 ID·시각·도구 이름·결과(후보 있음/없음/거부)·클라이언트 ID만 남기고, 검색어·조건은 남기지 않아요. 요청 횟수는 가명 ID × 도구로 세요.
   - 스위치: MCP 전체(켬/끔)를 둬요. rooms·notices가 `링크만`·`끔`이면 그 도구도 빠져요. 둘 다 빠지면 동의 시트 대신 "지금 연결할 수 있는 도구가 없어요"가 떠요.

시험 가능한 완료 기준
- 도구 목록 스냅샷에 쓰기 도구 0개. MCP 호출 중 게이트웨이 LLM 호출 0건.
- 예약자 이름·회의 제목을 넣은 시험 장부로 불러도 `rooms_find_free` 응답에 그 값 0건, 응답 스키마에 그 칸과 방별 일정 없음.
- 본문에 카나리를 넣은 시험 공지로 불러도 `notices_search` 응답에 본문 0건, 허용 밖 게시판 공지 0건.
- 토큰 없음, `aud`가 다른 토큰, 미등록 클라이언트, 동적 등록 시도, 만료 토큰은 모두 거부돼요.
- 모의 IdP에서 계정을 끄면 늦어도 10분 안에 MCP 호출과 갱신이 거부돼요(걸린 시간 기록). [끊기]·"모든 기기 로그아웃" 뒤의 갱신도 거부돼요.
- 링크를 열기만 해서 생긴 예약 0건, 남의 링크 열림 0건, 감사 로그를 뺀 MCP 경로 DB 쓰기 0건, MCP 감사 로그의 검색어·조건 카나리 0건.
- rooms·notices를 `링크만`·`끔`으로 하면 그 도구가 목록에서 빠지고, MCP 스위치를 끄면 연결이 거부돼요.
- 시연 시나리오 통과(모의 데이터): 동의 → 조회 → 링크 → 앱에서 예약, 연결 끊기, 퇴사 차단.

| S2 | 결과 시트 | 종류 칩·되묻기, 담당·공지·회의실 카드, 확인 시트, 공개 미리보기, 막힘 카드, 링크 카드, MCP 링크로 열린 후보("Claude에서 가져온 후보예요") | F1, F2, F3, MCP | 모두 |
| S3 | 같이 채워요 판 | 층별 요청 쓰기("우리 층 모두에게 보여요")와 가림 줄, +1·거두기, "같은 상품 같아요" 표시 | F3 | 직원(내 층), 총무(전 층) |
| S4 | 총무 운영 | 합치기 제안함([합치기]·[따로 두기]), 합친 기록·되돌리기, 예산·최소 몫·표 상한·주기 마감 표시 글자, 주문안 확정·내보내기 | F3 | 총무 |
| S5 | 분장표 수정 제안함 | 자기 부서 행에 쌓인 "틀렸어요" 기록 묶음 목록, 분장표 파일 다시 올리기(확인 시트) | F1 | 분장표 주인 |
| S6 | 내 것 | 내 예약·요청·표(요청 상태 포함), 저장하는 것 안내, 내 역할 진입점, 연결된 AI 앱(앱 이름·연결한 날·[끊기]), 모든 기기 로그아웃 | F1~F3, MCP | 모두 |

- 아래 탭은 묻기(S1) / 같이 채워요(S3) / 내 것(S6)이에요. "같이 채워요 단독" 모드에서는 묻기 탭을 숨기고 S3가 첫 화면이에요.
- 진입점: 총무는 S3 머리 [운영]과 S6 "내 역할"로 S4에 가요. 분장표 주인은 S6 "내 역할"로 S5에 가요. 역할이 없는 사람에게는 진입점이 안 보여요.
- 운영자 전용 화면은 S1~S6에 없어요. 운영 설정과 묶음 통계만 있어요(화면 번호 없음).
- MCP 연결 동의는 새 화면 번호 없이 S6 위에 뜨는 동의 시트예요(M4).

## 비기능·보안 요구사항

| 데이터 | 등급 | 어디까지 가나 | 저장 | AI로 보내나 |
|---|---|---|---|---|
| 묻기 입력 원문 | 1(2·3이 섞일 수 있음) | 브라우저 검사 → 서버 메모리 → 게이트웨이 | 안 해요 | 무보관 모델만 |
| 업무 분장표 | 1 | 가져오기 → DB | 해요 | 후보 행만 |
| 공지 본문 | 1(허용 게시판만) | 사본 가져오기 → 색인 | 색인 + 원문 링크 | 안 보내요(규칙·색인 검색) |
| 회의실 목록·빈 시간 | 1(빈 시간 = 사람이 없는 시간) | 어댑터 → 이름 없는 타입 → 화면 | 예약 기록(가명 ID) | 안 보내요 |
| 남의 예약자 이름·회의 제목 | 1~2 | 어댑터에서 버려요 | 안 해요 | 안 보내요 |
| 탕비실 품목 이름·표 | 0~1 | 서버 DB | 품목 이름·투표 행(가명 ID)·층 | 품목 이름·층·표 수·금액·이유 코드(투표자 없음) |
| "틀렸어요" 기록 | 1 | 피드백 경로 → 서버 | 종류·행·이유 코드·시각만(사용자·가명 ID 없음) | 안 보내요 |
| MCP 회의실 결과(빈 방 후보) | 1 | MCP → 허용 클라이언트 | 안 해요 | 우리 게이트웨이는 안 거치고, 허용 클라이언트의 모델로 가요 |
| MCP 공지 결과(제목·게시일·링크) | 1 | MCP → 허용 클라이언트 | 안 해요 | 위와 같아요. 본문은 안 가요 |
| MCP 승인(갱신 토큰) | 1 | 인가 서버 | 해요(끊기·로그아웃·퇴사 때 폐기) | 안 보내요 |
| 키·토큰·주민번호·비밀번호·건강 정보 | 3 | 입력 단계에서 막아요 | 안 해요 | 안 보내요 |

- **원문 비보관과 샐 틈 막기**
  - 로거·오류 보고에서 본문 칸을 빼요. 오류 보고·분석·세션 녹화 도구는 쓰지 않거나 본문 칸을 빼요. 프록시·APM의 본문 기록은 꺼요.
  - 입력 원문은 URL에 넣지 않고 POST 본문으로만 보내요. 브라우저 저장소에 두지 않고 페이지 메모리에만 둬요. 입력창은 자동 완성을 꺼요.
  - 모듈 사이 대화 기억은 없어요.
- **공통 입력 검사**: 묻기 입력창과 요청 쓰기 칸 모두, 브라우저와 서버 양쪽에서 해요. 키·토큰은 잠그고, 이메일·IP는 바꾸고, 등급 3은 막아요. 가림 줄은 입력 칸 바로 아래에 보여 줘요.
- **묻기·게시 분리**: `/ask`는 아무것도 저장·게시하지 못해요. 가능하면 DB 역할도 나눠요. 게시는 품목 이름만 담아 공개 미리보기 확인을 거쳐요.
- **쓰기 경계**: LLM에는 쓰기 도구가 없어요. 쓰기 카드에는 서버가 서명한 짧은 수명의 제안 토큰만 붙어요. 사람의 확인은 쓰기마다 정확히 한 번이에요.
  - 회의실: 주 버튼이 plan을 만들고 확인 시트를 열어요. [예약하기]가 plan_id로 실행해요.
  - 게시: 공개 미리보기의 [올리기]가 토큰과 확정된 이름으로 plan 만들기와 실행을 한 번에 해요.
  - 고정 버튼 쓰기(+1·표 거두기·따로 두기·합치기·되돌리기·주문안 확정·분장표 파일 다시 올리기·AI 앱 연결 끊기)는 plan 없이 같은 실행 함수를 거쳐요(권한·상태 재검사, 멱등 키).
  - 확인 시트를 거치는 것: 예약·예약 취소·합치기·되돌리기·주문안 확정·분장표 파일 다시 올리기·AI 앱 연결 끊기·모든 기기 로그아웃. 바로 실행하는 것: +1·표 거두기·따로 두기.
  - 버튼은 누르면 잠겨요. 모듈별 허용 목록 밖의 도구는 부를 수 없어요.

| 역할 | 할 수 있는 것 | 못 하는 것 |
|---|---|---|
| 직원 | 묻기, 내 이름 예약·취소, 내 층 게시·+1·거두기, 내 것 보기 | 합치기 확정, 주문안, 분장표 수정, 남의 예약 정보 |
| 총무 | 직원 권한 + 합치기 확정·되돌리기, 예산·최소 몫·표 상한 설정, 주문안 확정·내보내기 | 투표자·질문 원문 보기 |
| 분장표 주인 | 직원 권한 + 자기 부서 행에 쌓인 기록 보기, 분장표 파일의 자기 부서 행을 고쳐 다시 올리기 | 다른 부서 행 수정 |
| 운영자 | 감사 로그, 10명 이상 묶음 통계, 오류·AI 비용, 끄기 스위치·운영 설정(회의 길이 기본값·요청 횟수 제한) 바꾸기, MCP 클라이언트 등록(보안팀 승인 목록에 오른 것만) | 질문 원문, 투표자(DB 읽기 역할을 나눠 다시 잇지 못하게), 개인 조건, MCP 검색어·조건 |

- **권한 계산**: 서버가 요청마다 (역할, 층, 모듈, 동작)으로 계산해요. 세션에는 "누구인지"만 담아요. 총무·운영자는 IdP 그룹(없으면 운영자가 관리하는 역할 표)에서, 분장표 주인은 부서 클레임이 행의 주인 부서와 같을 때 받아요. 진입점을 숨기는 것과 별개로 서버가 검사해요.
- **감사 로그**: 내용은 남기지 않아요.
  - 묻기: 가명 ID·시각·모듈 종류·결과(카드 만듦/못 찾음/잠김)만 남겨요. 분장표 행 ID·공지 ID·슬롯 값은 남기지 않아요. "누가 어떤 업무를 물었나" 이력이 생기지 않게 하려고요.
  - 쓰기: 가명 ID·시각·모듈·동작·결과만 남겨요.
  - MCP: 가명 ID·시각·도구 이름·결과·클라이언트 ID만 남겨요. 검색어·조건은 남기지 않아요.
- **세션·퇴사 차단**: 접속 관문 → 사내 SSO(MFA·패스키) → 서버 세션(httpOnly 쿠키) 순서예요. 토큰은 브라우저에 두지 않아요. 퇴사하면 늦어도 10분 안에 웹 세션과 MCP 승인이 모두 끊겨요. 개인 폰 세션은 8시간이고, "모든 기기 로그아웃"은 MCP 승인도 폐기해요. 2주 동안은 모의 OIDC로 시작해요.
- **접속 관문과 MCP**: claude.ai는 Anthropic 클라우드 주소 대역에서 붙어요. 관문에서는 `/mcp`와 인가 경로만 그 대역에 열어요. 여는 데는 보안팀 승인이 필요해요.
- **AI 게이트웨이**: 하나로만 부르고, 무보관 모델로 고정해요. 등급 0·1만 통과하고, 요청 단위로 상태를 두지 않아요. 무보관 대상이 아닌 기능(파일 API·배치·MCP connector)은 쓰지 않아요. 구조화 출력 스키마에 사내 정보를 넣지 않아요.
  - 회사 명의 무보관 계약이 확인되기 전에는 실제 직원 파일럿을 시작하지 않아요. 그 전 측정은 가상(등급 0) 분장표·질문으로만 실제 모델에 보내요. 화면에 "모의 모델" 상태는 따로 두지 않아요.
  - MCP 결과는 우리 게이트웨이를 거치지 않고 허용 클라이언트의 모델로 가요. 그래서 그 몫은 허용 클라이언트 정책("MCP 읽기 채널" 4번)과 최소 출력(빈 방 후보, 공지 제목·링크)이 맡아요.
- **시연 데이터 띠**: 모의 어댑터가 하나라도 켜져 있으면 앱 위쪽에 띠 하나("시연 데이터로 돌아가요")를 둬요. 누르면 어떤 데이터가 모의인지 보여 줘요.
- **주입 방어**: 모듈 호출에는 그 모듈 읽기 자료만 줘요. 10일 차에 공지·요청·분장표 속 지시문 주입 시험을 해요. MCP 출력은 제목·게시일·링크·방 정보뿐이라 본문 주입 위험은 작고, 주된 방어는 쓰기 도구가 없다는 점이에요.
- **끄기 스위치**(운영 설정, 운영자만 바꾸고 감사 로그에 남겨요): 모듈마다 `켬 / 링크만 / 끔`이에요.
  - 링크만: 그 종류로 분류되면 S2에 "이 일은 그룹웨어에서 해요" 링크 카드가 떠요.
  - 끔: 라우터가 그 종류를 후보에서 빼고, 분류되면 담당 안내로 보내요. 예시 칩과 진입점도 숨겨요.
  - 세부 스위치: 회의실 쓰기(켬/끔), MCP 전체(켬/끔). 공지 요약과 S5 전체 기능은 이번 2주에 없어서 각각 "꺼짐"·"목록만"으로 고정이에요.
  - "같이 채워요 단독" 모드는 navi·notices·rooms를 모두 끈 상태예요.
- **접근성·모바일**: 직원 화면은 폰 너비·한 손 기준이고, 입력창과 주 버튼은 아래쪽에 둬요. 결과는 바닥 시트로 띄우고 뒤로 가기 한 번이면 닫혀요. 카드 머리 라벨은 제안·확정·안내·막힘 넷이고 글자로 보여 줘요. 색만으로 가르지 않아요. S4·S5는 PC 우선이고, 폰에서는 요약과 확정·저장만 해요.

## 가정과 열린 질문

**사용자 확인(먼저 답이 필요해요)**
1. (답 받음) 읽기 전용 MCP(회의실 조회·공지 찾기)를 2주 안에 넣어요. 쓰기 도구는 열지 않아요(M1).
2. 회사가 쓰는 그룹웨어(네이버웍스·카카오워크·다우오피스·M365 등)는 무엇이고, 그 AI를 켰나요?
3. 회의실·탕비실·"누구한테 물어봐요"를 같은 창구(총무 한 팀)가 맡나요, 층마다 다른가요?
4. 이름은 "한 줄 데스크"와 "어디서 해요?" 중 무엇으로 할까요?
5. 무보관 계약 두 가지가 있나요? (가) 우리 앱이 쓸 모델의 회사 명의 무보관 계약(또는 사내 모델): 없으면 실제 직원 파일럿을 시작할 수 없어요. (나) 직원이 회사 명의로 쓰는 AI 클라이언트(예: claude.ai 조직)와 그 무보관 조건: 없으면 실제 데이터로 MCP를 켤 수 없어요.

**가정**
- 회사 명의 무보관 AI 계약이나 사내 모델이 있어요. 확인되기 전에는 등급 1 자료를 AI로 보내지 않고, 실제 직원 파일럿도 시작하지 않아요.
- 회사 IdP가 OIDC를 지원하고 퇴사 10분 차단을 보장해요.
- 업무 분장표가 한 장으로 있어요. 행마다 주인 부서가 있고, 창구는 팀·대표 메일 단위로 적혀 있어요.
- 사옥이 여러 층이고 층마다 탕비실이 있어요. 주문에는 정해진 주기가 있어요.
- 탕비실 구매는 회사 자체 카탈로그나 MRO로 총무가 기존 절차대로 해요.
- 시연은 모의 회의실 장부와 가상 직원으로 해요. 파일럿은 층 1~2개로 해요. 직원 화면은 한국어만 지원해요.
- MCP 시연은 모의 회의실 장부와 가상 공지(등급 0)로만 하고, 시험 클라이언트는 claude.ai 조직 커넥터 하나예요. 그 조직 소유자가 커넥터를 등록해 줄 수 있다고 가정해요.

**그 밖의 열린 질문**
- (사용자에게 물을 것) 운영 주인이 기능마다 다르면 "같이 채워요 단독" 모드(묻기 탭 숨김)로 가요. 이 모드도 괜찮은가요?
- (보안팀) 접속 관문에서 `/mcp`와 인가 경로를 Anthropic 주소 대역에 열어 줄 수 있나요?
