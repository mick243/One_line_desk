# 홈 "할 수 있는 일" 목록 회의 (2026-11-03)

안건: 홈의 "할 수 있는 일" 목록(`apps/web/src/screens/Home.tsx` `.menu-list`, 기능마다 아이콘·이름·한 줄 설명)이 아래 탭바와 역할이 겹쳐요. 이 목록이 꼭 있어야 할까요? 사용자가 홈 채팅을 써 보고 제기했어요.

참석(모두 에이전트): 기획·UX, QA·접근성, 시장·사례 조사

## 확인한 사실

- 목록과 탭바는 같은 조건(`modules[m] !== 'off'`)으로 걸러져요. 그래서 둘이 보여 주는 기능은 늘 같아요. 목록으로만 갈 수 있는 페이지는 없어요.
- 홈 채팅(`homeAsk`)은 기본값(`DEFAULT_OPS_SETTINGS`)도 출시값(`LAUNCH_OPS_SETTINGS`)도 켬이에요. 하지만 운영자가 끌 수 있는 스위치예요.
- 휴대폰에서는 목록이 어차피 첫 화면 밖에 있어요. 위에서부터 인사, 채팅 칸·칩, 대화, 오늘 카드 순서로 쌓이기 때문이에요.
- 한 줄 설명(링크만·쓰기 끔 문구 포함)은 기능 페이지 머리의 `summary`에도 같은 뜻으로 있어요.
- 시험·`scripts/smoke.mjs`에는 목록을 쓰는 곳이 없어요. 고칠 곳은 문서(`docs/화면설계.md`, README)와 CSS예요.
- 이전 QA에는 목록을 지적한 항목이 없어요. M9 "홈에도 입구가 없어요"는 오히려 홈에 입구가 있어야 한다는 쪽이에요.
- 사례
  - Slack 모바일·토스·Teams는 홈을 "나에게 해당하는 것"으로 채워요. 탭에 있는 기능을 홈에서 다시 늘어놓지 않아요.
  - 네이버웍스는 탭에 없는 서비스만 홈에 보여 줘요. 이 내용은 도움말 검색 요약만 봤어요.
  - NN/g "Duplicate Links"는 한 화면에 같이 보이는 겹친 링크를 지나친 중복으로 봐요.

## 위험

- **높음**: 목록을 아예 지우면 홈이 거의 빈 화면이 되는 조합이 있어요.
  - 조합: 채팅 끔 + 회의실·같이 채워요 끔 + 문의하기 켬 아님.
  - 이때 홈에는 인사말만 남아요.
- **중간**: 화면 읽기 프로그램 사용자는 기능 설명을 기능 페이지에 들어가서야 들을 수 있어요. 탭은 이름만 읽어 줘요.
- **낮음**: 탭 이름(0.6875rem, 줄 바꿈 없음)이 큰 글자·좁은 화면에서 잘릴 수 있어요. 목록이 없어지면 남는 입구가 탭뿐이에요.

## 권고 (세 담당 합의)

- **홈 채팅이 켜져 있으면 목록을 숨기고, 꺼져 있을 때만 보여 줘요.**
  - 지금 내 예약·내 문의 작은 카드를 숨기는 방식(`!homeAsk && …`)과 같아요.
  - 홈 채팅이 켜진 홈은 Slack·토스처럼 "나에게 해당하는 일"에 집중해요.
- 새로 온 사람을 위해, 오늘 카드가 비었을 때 문구를 한 줄 덧붙여요.
  - 예: "이번 주에 나에게 해당하는 일이 없어요. 아래 탭에서 문의·회의실·공지·같이 채워요를 할 수 있어요"
- 탭 이름이 큰 글자(200%)·320px 폭에서 잘리지 않는지 같이 확인하고, 잘리면 고쳐요.

버린 안
- **완전 삭제**: 채팅을 끈 회사에서는 홈이 비어요.
- **기능 소개를 채팅 예시 칩으로 옮기기**: 홈 칸은 "예약·신청을 하지 않아요"라고 약속한 칸이에요. 기능 소개 칩을 섞으면 칸이 무엇을 하는지 흐려져요.
- **접어 두기**: 한 번 더 눌러야 하는데, 얻는 것은 탭바와 같아요.
