# 그룹웨어(하이웍스·다우오피스·플로우)와 무엇으로 차별할까 — 회의 (2026-10-31)

- 참석: 리드(진행), 시장·경쟁사 조사(웹), 제품·UX 기획, 고객사 구매·정보보안팀(가상). 모두 에이전트예요. 코드는 고치지 않았어요.
- 기준: `docs/기획서.md`, `docs/PRD.md`, `docs/ADR.md`, `CLAUDE.md`, MCP 코드(`core/tool-registry.ts`, `modules/mcp/`), 경쟁사 공식 페이지·기사(아래 출처, 2026-10-31 확인).
- 웹 조사는 공식 페이지에 없는 내용을 "확인 못 함"으로 남겼어요. 계약·제안서에 쓰기 전에 다시 확인해요.

## 한눈에

1. **범용 "AI 비서"(요약·작성·검색)로는 차별이 안 돼요.** 세 곳 모두 GPT·Gemini·Claude 같은 외부 모델을 붙여 기본 제공해요. 하이웍스는 모든 상품에 AI 채팅을 넣었고, 다우오피스는 회사 단위 크레딧(월 5만 원~)으로 "실행"까지, 플로우는 워크 에이전트와 공식 MCP까지 갔어요.
2. **우리는 그룹웨어를 대체하지 않고 옆에 붙어요(3명 모두).** 결재·메일·메신저·문서·조직도·근태 원장·회의실 장부·공지 원본은 그룹웨어 몫이에요. 겹치면 운영 스위치 `링크만`으로 물러나요(ADR-12). 이게 "보완재"라는 걸 제품 구조로 보여 줘요.
3. **차별 축은 셋이에요.**
   - **A. "이 일은 어디서·누가·무엇부터?"를 근거와 함께 한 줄로 답하는 앞단.** 세 곳 모두 조직도(사람)는 있지만 "업무 분장"에 근거로 답하지 못해요. 우리는 분장표 행 원문을 그리고 근거가 없으면 카드를 만들지 않아요(ADR-09). 이어서 팀 문의·휴가 요청까지 끝나요(ADR-16·24).
   - **B. AI를 써도 사고가 나지 않는 구조를 공개 정책으로 보여 주기.** 경쟁사 문서 어디에도 "무엇은 바로 실행하고 무엇은 사람이 확인하나"가 없어요. 우리는 LLM·MCP 쓰기 도구 0개, 확인한 plan·고정 버튼만 실행, 실행 순간 재검사, 자동 실행 허용 목록(회의실·장비·탕비실, 운영 기본 끔), 원문 비보관·감사 칸 제한·7일 보관·이름 비노출을 시험으로 지켜요(ADR-03·10·19·21).
   - **C. 그룹웨어에 없는 빈칸 하나: 탕비실 "같이 채워요".** 자유 문장을 같은 품목으로 합치고 1인 1표, 층별 최소 몫, 줄마다 이유가 붙은 주문안이에요. 세 곳은 비품 "예약" 수준이거나 확인되지 않았어요.
4. **MCP에서는 플로우가 먼저 나갔어요.** 공식 원격 MCP(ChatGPT 앱·Claude 커넥터 등록, OAuth, 본인 권한 상속), 도구 40개 중 **쓰기 19개**를 바로 줘요. 쓰기 전 사람 확인 단계는 문서에 없어요. 하이웍스는 공식 MCP 없음(비공식 메일 MCP만), 다우오피스는 확인 못 함. → 우리 MCP의 차별은 도구 수가 아니라 **"읽기만, 쓰기는 앱 확인 링크로, 허용 클라이언트 두 겹, 갱신 때 재직 확인, 출력 칸 화이트리스트"라는 노출 정책**이에요.
5. **고객사 보안팀 평가: "설계는 좋은데 아직 증명 전".** 실제 IdP·근태·그룹웨어 연결, 인증(ISMS 등), 온프레미스, 국내 리전 운영이 아직 없어요. 다우오피스는 ISMS, 플로우는 CSAP·ISO 27001과 구축형(폐쇄망)이 있어요. 이 차이는 메시지로 덮지 말고 로드맵으로 보여 줘요.

## 2. 경쟁하지 말 것

- 결재·메일·메신저·문서·조직도·근태 원장·회의실 장부·공지 게시. 두 벌 장부가 생기고, "앱을 또 써야 해요?" 반발이 오고, 원문 비보관·7일 보관 원칙과 맞지 않아요. PRD도 결재·업체 연동을 범위 밖으로 뒀어요.
- 붙는 방식이 강점이 돼요: `링크만` 스위치, 쓰기 결과는 그룹웨어로(휴가 승인 → 근태 어댑터, 회의 초대 → 그룹웨어 캘린더·.ics), 어댑터만 바꾸면 그룹웨어가 바뀌어도 직원 경험이 같아요.

## 3. 메시지(과장 없이)

1. **"회의실·공지는 그룹웨어가 원본이에요. 겹치면 우리는 링크로 물러나요."**
2. **"그룹웨어에 없는 두 가지를 해요: 업무 분장을 근거로 '어디서·누가'를 답하고, 층별 탕비실 요청을 근거 있는 주문안으로 모아요."**
3. **"AI가 답을 지어내거나 몰래 실행하지 못하게 구조로 막았고, 시험으로 보여 드려요."** — 경쟁사가 위험하다는 말이 아니라 "우리는 증명할 수 있다"로만 써요.

**포지셔닝 문장(권고)**
- 대표: **"그룹웨어 옆 안내 데스크 — 이거 어디서 해요? 한 줄이면 담당·근거·다음 할 일을 카드로 드려요."**
- 보안팀·도입 담당자용: **"AI를 써도 사고 나지 않는 사내 창구 — 근거 없는 답 없음, 몰래 쓰기 없음, 물은 말은 남기지 않음."**
- 대표 문장의 걸림돌: 앞문(종류를 고르지 않는 한 줄 입력)을 ADR-02 개정 때 없앴어요. 홈에 "어디서 해요?" 입력을 되살릴지 결정이 필요해요(ADR-22에서 미룬 안건).

## 4. 보안 검토서에 쓸 체크리스트("주장 → 강제 장치 → 확인 방법")

- 원문 비보관: POST 본문·요청 메모리에서만, 카나리 시험(DB·로그·URL) 매 CI. 예외는 [보내기]한 문의·휴가 요청만 7일.
- 감사 로그 정해진 칸만: `core/audit.ts`가 검색어·슬롯·행 ID 거절.
- 법정 접속기록 분리: `access_log` IP·정보주체 표시만, 고칠 수 없음, 1년.
- AI 등급 게이트: 게이트웨이 하나, 등급 2 거부, 무보관 계약 전 등급 0만, 연차는 모델에 안 보냄.
- LLM·MCP 쓰기 도구 0개: 도구 목록 스냅샷 시험, 주입 시험 쓰기 0건. 예외(자동 실행 허용 목록)도 숨기지 않고 적어요.
- MCP: 등록 기밀 클라이언트 + 보안팀 승인 목록, `aud` 검사, PKCE, 갱신 때 재직 확인(퇴사 10분), 출력 칸 화이트리스트.
- 회사별 분리: 회사마다 서버·DB·IdP·비밀 값, 회사 목록 없음.
- 7일 보관·이름 비노출: 남의 예약자·투표자 칸이 타입에 없음, 바깥 서비스는 최소 칸만.

## 5. 보안팀이 걸 지점과 대응

| 지점 | 대응 |
|---|---|
| 국외 호스팅(시연: Vercel·Fly 도쿄) | 시연에 실제 자료 금지를 계약에 적고, 파일럿은 국내 리전·사내 관문 |
| 실제 IdP·근태·그룹웨어 연결 전 | 스테이징에서 회사 IdP의 `max_age`·`auth_time`·로그아웃 확인, 퇴사 차단 재측정 |

| 인증·외부 감사 없음 | 위탁 계약·취약점 점검 권리·개인정보 영향 평가를 먼저 제공, 인증은 로드맵 |
| 외부 AI 모델 | 계약 전 AI 끔(규칙만), MCP는 별도 승인 건 |

## 6. 넓힐 후보

| 후보 | 가치 | 원칙과 맞음 | 메모 |
|---|---|---|---|
| ① 신규 입사자 온보딩(첫 2주 할 일을 분장표 행과 연결) | 높음 | 높음 | 분장표·공지 재사용, 진행 기록은 짧게 |
| ② IT 오류 문장 → FAQ 원문 단계 → 티켓 초안 | 높음 | 높음 | 이미 PRD 다음 2주 1순위 |
| ③ MCP `navi_find_rows` 공개(담당 찾기) | 높음 | 높음 | 사람 이름이 원래 없음, 앱 문의 링크와 묶음 |
| ④ 부서 간 문의 처리 통계(분장표 처리 기간 대비, 부서 단위 셈만) | 높음 | 조건부 | 7일 보관이라 셈만 남겨요 |
| ⑤ 회의실 노쇼 정리(체크인 없으면 "놓아줄까요?" 확인) | 중~높음 | 높음 | 자동 해제가 아니라 예약자 확인 |
| ⑥ 여러 시스템(그룹웨어·메신저·ITSM)을 한 줄로 묶는 허브 | 높음 | 높음 | 어댑터 구조를 가장 잘 살림, 실제 연동 비용 큼 |
| ⑦ 사내 카페 주문 | 중 | 조건부 | 토스POS연동회의 참고, 사용자 결정·ADR 먼저 |
| ⑧ 사내 규정 Q&A | 높음 | 조건부 | "해석"이 아니라 "원문 인용 + 담당 팀"으로 좁히고, 그룹웨어 AI와 겹치면 링크만 |

권고 순서: ① → ② → ③ → ④ → ⑥. ⑦은 결정 뒤, "나만 안 돼요?" 같은 신고 묶기는 원문을 남기지 않는 원칙과 맞지 않아 넣지 않아요.

## 7. 성공 지표 후보(파일럿)

1. 파일럿 층 직원 주 1회 이상 사용 40%
2. 담당 찾기 "못 찾음" 30% 이하, "틀렸어요" 10% 이하
3. 7일 안 문의·휴가 요청 처리 80%, 처리 전에 지워진 요청 0건
4. 원문 카나리 유출·잘못 실행 0건(1건이면 해당 스위치를 바로 꺼요)
5. 총무 탕비실 주문 준비 시간 감소와 층별 몫 이의 건수(측정 방법 따로 정해요)

## 8. 회의 중 찾은 문서 정리 거리

- ADR 목록 표와 ADR-16 본문이 문의 보관을 아직 "90일"로 적고 있어요(ADR-21로 7일).
- PRD 일부가 앞문 시절 문구예요.

## 결정할 것

- 대표 포지셔닝 문장과, 그 전제인 홈 "어디서 해요?" 앞문을 되살릴지
- 넓힐 후보의 우선순위(권고 ① 온보딩 → ② IT 오류 → ③ MCP 담당 찾기)
- 인증(ISMS 등)·국내 리전 운영·온프레미스를 로드맵에 언제 둘지
