# 장애 런북 — 첫 조치 (2026-10-29)

- 근거: `docs/배포준비회의_2026-10-29.md` C7·F8·쟁점 2·쟁점 5
- 누가 써요: 파일럿 운영자(정보보안팀)와 대리 1명
- 원칙
  - 기능 하나의 문제는 **스위치**로 끄고, 바닥 문제(5xx 급증·흰 화면·로그인 전부 실패)는 **되돌리기**로 풀어요.
  - 직원이 쓴 글·이름·검색어는 기록·알림·대화에 옮기지 않아요. 요청 번호(`x-request-id`)·판(`x-desk-build`)·시각은 적어도 돼요.
  - 서버를 다시 띄우면 모두 로그아웃돼요(세션이 메모리에 있어요, 앞선 회의 F1 전까지). 재시작은 마지막 수단이에요.

## 0. 먼저 볼 것(5분)

1. 관문 안에서 `/health/ready`: `ok`, `db`, `retention`, `build`를 봐요. `/health/live`가 200이면 프로세스는 살아 있어요.
2. 떠 있는 판(`build`)이 마지막으로 배포한 커밋이 맞는지 봐요.
3. 로그 건수(사내 수집기, 지난 15분)
   - `server-error`: 서버 오류
   - `retention-failed`: 7일 보관 지우기 실패(`step`에 단계 이름)
   - `db-pool-error`: DB 연결 문제
   - `idp-unreachable`: 회사 로그인에 닿지 못함
   - `idp-no-auth-time`: 회사 IdP가 인증 시각을 주지 않아 로그인을 받지 않음
   - `server-started`: 서버가 다시 뜸(업무 중이면 원인을 찾아요)
4. 마지막 배포 시각과 바꾼 스위치(운영 설정 감사 로그)를 봐요.

## 1. 스위치 바꾸는 법

아직 운영 설정 화면이 없어요(스위치 CLI는 P1). 지금은 둘 중 하나로 바꿔요.

**가. 운영자 계정으로 로그인한 브라우저(우선)**: 개발자 도구 콘솔에서 불러요. 운영자 가명으로 감사 로그에 남고, 서버는 바로 막아요. 이미 열린 화면은 새로 고쳐야 바뀐 스위치를 봐요.

```js
const { csrfToken } = await (await fetch('/api/me')).json();
const put = (path, body) =>
  fetch(path, { method: 'PUT', headers: { 'content-type': 'application/json', 'x-csrf-token': csrfToken }, body: JSON.stringify(body) }).then((r) => r.json());
await put('/api/ops/flag', { flag: 'autoActions', value: false }); // 채팅 바로 실행 끄기
// await put('/api/ops/flag', { flag: 'roomsWrite', value: false }); // 회의실 쓰기 끄기
// await put('/api/ops/flag', { flag: 'mcp', value: false }); // MCP 끄기
// await put('/api/ops/switch', { module: 'rooms', value: 'link' }); // 회의실을 "링크만"으로
// await put('/api/ops/values', { rateLimitPerMinute: 10 }); // 분당 요청 상한 낮추기
```

**나. 운영자가 로그인할 수 없을 때(IdP 장애 등)**: DB에서 바꾸고 서버를 다시 띄워요. 서버는 뜰 때만 이 표를 읽어서, 다시 띄우기 전에는 반영되지 않아요(= 모두 로그아웃). 감사 로그에 남지 않으니 장애 기록에 꼭 적어요.

```sql
-- 운영 설정은 ops_settings(id = 1)의 overrides(jsonb) 한 줄에 있어요.
update ops_settings set overrides = coalesce(overrides, '{}'::jsonb) || '{"autoActions": false}'::jsonb where id = 1;
-- 회의실 쓰기 끄기: '{"roomsWrite": false}' / MCP 끄기: '{"mcp": false}'
```

## 2. 증상별 첫 조치

| 증상 | 첫 조치 | 다음 |
|---|---|---|
| 채팅이 묻기만 했는데 예약·대여를 했어요 | `autoActions` 끔 | 잘못 들어간 예약을 본인에게 알리고 취소를 안내해요. 그 문장 모양을 `packages/shared/src/rooms-chat-samples.ts` 금지 표에 더해요(문장 원문 대신 모양만) |
| 예약이 겹치거나 장부와 다르게 보여요 | `roomsWrite` 끔, 회의실을 `link`(링크만) | 장부 담당과 대조해요. 고칠 때까지 그룹웨어로 안내해요 |
| MCP(외부 AI 앱)가 이상해요 | `mcp` 끔 | 클라이언트 폐기는 DB에서 해요(ops 스크립트는 P1). 정보보안팀에 알려요 |
| 요청이 몰려요(429가 늘어요, 느려요) | `rateLimitPerMinute` 낮춤 | 몰린 경로를 로그로 봐요(경로만 남아요) |
| 회사 로그인이 안 돼요(`idp-unreachable`) | 앱에서 할 일은 없어요 | IT 창구에 알리고 사내 공지를 내요. 이미 들어온 사람은 계속 써요 |
| 회사 로그인이 모두 실패해요(`idp-no-auth-time`) | IdP 담당에 `max_age`·`auth_time` 지원을 확인해요 | 급하면 바로 앞 판으로 되돌려요(3절). 회사 IdP 바꾼 날이면 그 설정부터 봐요 |
| DB가 안 돼요(`/health/ready` 503, `db-pool-error`) | 관리형 DB 상태를 봐요 | `/health/live`는 200이라 재시작하지 않아요. 오래가면 사내 공지를 내요 |
| 보관 지우기가 실패해요(`retention-failed`) | 5분 뒤 저절로 다시 돌아요 | 같은 `step`이 계속 실패하면 그날 안에 고쳐요(7일 보관 약속) |
| 배포 직후 5xx가 늘거나 흰 화면이에요 | 3절 기준에 걸리면 되돌려요 | 원인을 찾은 뒤 다시 배포해요 |
| 응답·로그·관문 로그에 직원 글이 보여요(카나리) | **바로 되돌려요** | 정보보안팀에 바로 알려요. 보인 곳·기간만 적고 글은 옮기지 않아요 |
| 업무 중에 서버가 다시 떴어요(`server-started`) | 원인을 찾아요(메모리·노드 이동) | 한 주에 한 번을 넘으면 세션 표(앞선 F1)를 당겨요(쟁점 2) |
| 시연이 더럽혀졌어요(이상한 글·스위치) | 시연 컨테이너를 다시 띄워요(tmpfs라 처음으로 돌아가요) | 명단 밖으로 넓힌 시연이면 `DESK_DEMO_WIDE=true`로 띄워요(문의 저장·운영 설정 바꾸기를 막아요) |

## 3. 되돌리기

- 기준(배포 뒤 30분, 수치는 회사가 확인해요)
  - `/health/ready` 503이 2분 이어져요.
  - 5xx가 5분에 10건을 넘거나 1%를 넘어요.
  - IdP는 정상인데 로그인 실패가 10분에 5건을 넘어요.
  - 지원 브라우저에서 흰 화면이에요.
  - 직원 글·내용이 응답·로그에 보여요 → 기준과 상관없이 바로예요.
- 방법
  1. 바로 앞 이미지 태그(커밋)로 같은 환경 값을 넣어 다시 띄워요(`--stop-timeout 50`).
  2. 마이그레이션은 되돌리지 않아요. 한 배포에서는 넓히기만 해서 앞 판이 그대로 떠요.
  3. `/health/ready` 200과 `build`가 앞 판인지 보고, `node scripts/smoke.mjs <주소>`를 돌려요.
  4. 모두 로그아웃됐다고 사내 공지를 내요.
