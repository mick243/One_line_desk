# 병가 추가 준비(2026-11-01)

- 요청: 휴가 요청(ADR-24)에 병가를 더할 준비를 해 달라고 했어요.
- 이 문서는 구현 전에 볼 것을 모았어요. 지금 코드가 병가를 어떻게 다루는지, 원칙과 부딪히는 점, 정해 주셔야 할 것, 바꿀 파일과 시험이에요.
- 코드는 아직 바꾸지 않았어요.

## 1. 지금 상태

| 곳 | 지금 하는 일 | 병가를 넣으면 |
|---|---|---|
| `navi/leave.ts` `NOT_ANNUAL` | "병가·육아·경조…"가 든 질문은 연차 질문이 아니라고 보고 연차 카드를 붙이지 않아요 | 병가 질문은 따로 알아보고 병가 카드를 붙여요 |
| `navi/leave.ts` AI 질문 해석 | 모델에게 "병가는 연차가 아니에요(false)"라고 알려요 | 종류(연차·병가)를 고르게 바꿔요(등급 1, 질문 글만 보내요) |
| `LeaveUse`(어댑터) | 날짜와 하루·반나절만 있고, 종류·사유는 받지 않아요 | 종류(연차·병가)를 더해요. 사유는 여전히 받지 않아요 |
| 남은 연차 계산 | 근태 기록의 모든 쓴 날을 연차에서 빼요 | 병가는 연차에서 빼지 않아요. 병가 쓴 날은 따로 세요 |
| `navi_inquiries` kind=leave | 휴가 요청 하나에 날·하루/반차만 있어요 | 요청 종류(연차·병가) 칸을 더해요(마이그레이션 170) |
| 휴가 신청 검사 | 지난 날은 보낼 수 없어요 | 병가는 아픈 날 당일이나 다음 날에 내는 일이 많아서, 며칠 전까지 받을지 정해야 해요 |
| 입력 검사 `HEALTH_TERMS` | 진단명·알레르기 같은 건강 정보가 든 글은 보내기를 잠가요. "병가"라는 제도 이름은 막지 않아요 | 사유 칸에 병명을 쓰면 지금처럼 잠겨요. 이건 그대로 둬야 해요 |

## 2. 원칙과 부딪히는 점

1. **건강 정보를 받지 않는 원칙**
   - 병가 사유는 대개 건강 정보예요. 지금 규칙은 진단명을 보내기 전에 막아요.
   - 그래서 사유를 자유 글로 받으면 사람들이 병명을 쓰다 잠기는 일이 잦을 거예요.
   - 권하는 안: 사유를 정해진 선택지(예: "몸이 안 좋아요"·"병원 진료"·"가족 돌봄")로만 받고 자유 글은 두지 않아요.
2. **진단서 같은 증빙**
   - 앱은 파일을 받지 않고, 진단서는 건강 정보 덩어리예요.
   - **11/1 결정(보류)**: 앱에서 진료확인서를 올려 받는 안(아래 7절 조건을 모두 갖춘 뒤)으로 정했어요. 지금은 만들지 않고 보류해요. 그동안은 "진단서는 인사팀에 따로 내 주세요"라고만 알려요.
3. **개인 인사 자료(등급 2)**
   - 병가 쓴 날 수는 연차보다 더 민감해요.
   - 받은 팀은 지금처럼 그 요청 안에서만 봐요. 저장하지 않고 열 때마다 계산해요(ADR-24 그대로).
4. **AI**
   - 모델에는 질문 글만 보내고, 연차·병가 기록은 보내지 않아요(ADR-18 그대로).
   - 사람이 쓴 글이라 등급 1이에요.

## 3. 정해 주셔야 할 것

| 번호 | 정할 것 | 고를 수 있는 것 | 권하는 안 |
|---|---|---|---|
| 1 | 병가 사유를 어떻게 받을지 | 선택지만 / 선택지 + 자유 글(건강 정보는 잠김) / 받지 않음 | 선택지만 |
| 2 | 지난 날도 받을지 | 오늘부터만 / 지난 3일까지 / 지난 7일까지 | 지난 3일까지 |
| 3 | 반차 병가 | 하루만 / 하루·반차 | 하루·반차(연차와 같게) |
| 4 | 연간 병가 한도 표시 | 보이지 않음 / 회사 규정 일수와 쓴 날을 보여 줌 | 운영 설정에 한도를 두고, 두지 않으면 쓴 날만 보여 줌 |
| 5 | 진단서 안내 | 늘 안내 / N일 넘으면 안내 / 안내하지 않음 | 운영 설정 일수(기본 3일)를 넘으면 안내. 올려 받기는 11/1에 정했지만 보류(7절) |
| 6 | 유급·무급 | 회사마다 달라요 | 앱은 계산하지 않고, 인사팀이 그룹웨어에서 처리 |

## 4. 바꿀 곳(정해진 뒤)

- **공유** `packages/shared/src/api/navi.ts`
  - `LeaveDay`(또는 요청)에 종류 `annual | sick`를 더해요.
  - 병가 사유 선택지 목록을 둬요.
  - 받은 팀이 보는 계산에 병가 쓴 날 칸을 더해요.
- **어댑터** `apps/server/src/adapters/types.ts`·`mock/leave.ts`
  - `LeaveUse`에 종류를 더하고 가상 근태 기록에 병가 날을 몇 개 넣어요.
  - 실제 근태 시스템에 종류 칸이 있는지는 연결할 때 확인해요.
- **마이그레이션** `180_navi_sick_leave.sql`
  - 170(11/1 공가)이 `navi_inquiries.leave_type`(annual·official)과 사유 코드 칸을 이미 만들었어요. 여기에 `sick`을 더해요.
  - 병가 사유 코드 칸을 더해요(정해진 값만, 7일 보관 그대로).
- **서버** `navi/leave.ts`
  - 병가 질문을 알아보고, 병가 카드와 [병가 신청하기]를 붙여요.
  - 연차 계산에서 병가를 빼지 않아요.
- **서버** `navi/inquiries.ts`
  - 병가 요청 검사(지난 날 허용 범위·사유 코드)를 더해요.
  - 승인할 때 근태 기록에 종류를 같이 넣어요.
  - 알림 글은 "휴가 요청"처럼 내용 없이 "병가 요청이 왔어요"로 보내요.
- **웹**
  - 휴가 신청 양식에 종류를 고르는 칸을 더해요. 병가면 사유가 선택지로 바뀌고 진단서 안내가 나와요.
  - 받은 문의함에 "병가" 표시를 붙이고, 병가 쓴 날을 보여 줘요.
- **문서**
  - ADR-24 개정, 화면설계 문구, PRD 휴가 절을 고쳐요.

## 5. 시험(정해진 뒤)

- 병가를 승인해도 남은 연차가 줄지 않아요. 병가 쓴 날 수만 늘어요.
- 병가 사유는 정해진 코드만 받아요. 자유 글 칸이 오면 400이에요.
- 진단명이 든 글은 어느 칸이든 잠겨요(입력 검사 그대로).
- 지난 날 허용 범위 밖이면 거부해요.
- 알림·감사 로그에 병가 사유·날짜가 0건이에요.
- 받은 팀이 아니면 병가 요청을 볼 수 없어요.
- 모델 입력에 연차·병가 기록이 0건이에요(질문 글만 가요).

## 6. 지금 해 둔 것

- 11/1 공가를 먼저 넣으면서 휴가 종류 바탕을 만들었어요: 양식의 종류 고르기, 정해진 사유 코드, `LeaveUse.type`(연차가 아닌 날은 남은 연차에서 안 빼요), 받은 문의함 종류 표시. 병가는 여기에 종류 하나를 더하면 돼요.
- 병가 질문이 연차 카드로 잘못 가지 않게 막혀 있어요(`NOT_ANNUAL`). 병가를 넣기 전까지는 분장표 "휴가 신청" 행 담당 카드만 나와요.
- 입력 검사는 "병가"라는 말은 통과시키고 진단명만 막아요. 병가 화면을 붙여도 규칙은 바꾸지 않아도 돼요.

## 7. 진료확인서 올려 받기(11/1 결정, 보류)

- 결정: 앱에서 진료확인서를 올려 받는 안(검토한 세 안 중 3번)으로 정했어요. 지금은 만들지 않고 보류해요.
- 만들기 전에 모두 갖출 것
  - 민감정보 별도 동의 화면(개인정보보호법 제23조)과 처리방침 고치기
  - 주민번호가 찍힌 진료확인서 처리 근거 확인(제24조의2). 병원에 "병명 없는 진료확인서·통원확인서"를 달라고 안내해요
  - 받은 팀만 열람, 열 때마다 `access_log`에 남기기
  - 암호화해서 국내 저장소에 두기(Fly 디스크는 배포 때 지워지고 해외라 안 돼요)
  - 승인·반려 뒤 바로 지우기. 인사팀 보관은 회사 인사 시스템이 맡아요
  - PDF·JPG·PNG만, 크기 제한, 파일 종류 검사·악성 파일 검사, 촬영 정보(EXIF) 지우기
  - 파일은 AI로 보내지 않는 시험
  - ADR-18·21·24 개정과 보안팀·개인정보 담당·법무 확인
- 공가 증빙(훈련 통지서 등)도 같은 길을 쓸 거라 같이 보류해요.
