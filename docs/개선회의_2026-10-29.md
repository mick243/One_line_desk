## 5. 결정이 필요한 것

### 사용자 결정(이 저장소의 결정 기록)

1. **쟁점 3 골든셋 등급**: CLAUDE.md에 "팀이 만들고 검토한 시험 문장 파일은 측정 스크립트 안에서만 등급 0"이라는 예외 한 줄을 더하고, ADR-10을 보강할지 정해요.
2. **C3 집계 보관**: 사람·내용이 없는 집계를 ADR-21 7일 밖에 따로 둘지 정해요. 보안 권고는 이래요.
   - 저장하는 칸마다 서로 다른 사람 수가 10명 이상이어야 해요.
   - 겹치지 않는 구간 하나만 써요. 파일럿 규모면 ISO 주 단위예요. 하루 칸과 7일 창을 같이 내면 빼기로 숨긴 칸이 드러나요.
   - 숨긴 칸이 들어간 합계는 내지 않아요.
   - 보관은 1년을 권해요. S6 문구도 같이 고쳐요.
3. **백업 줄**: ADR-21에 백업 줄을 더할지 정해요. 권고는 이래요.
   - 본 DB 백업은 7일로 두고, S6에 "백업에서 최대 7일 더 남아요"를 적어요.
   - 접속기록만 따로 내보내 고칠 수 없는 저장소(객체 잠금 1년 이상)에 둬요.
4. **C2·D2 2단계**: 지금은 보류로 기록하고, 다시 볼 조건(3절)이 채워지면 결정에 올려요.

## 6. 서로 물은 것에 대한 답(합의한 권고)

- **파일럿 켜는 차례**(기획 권고, 회사 결정)
  - 1단계: 담당 찾기·공지·같이 채워요·문의만 켜요. 회의실 쓰기, `autoActions`, Slack은 꺼요. 회의실 쓰기를 끄면 초대도 같이 꺼져요.
  - 2단계: 실제 장부를 붙인 뒤 회의실 쓰기와 초대(앱 안 알림 + 캘린더 파일)를 켜요.
  - 3단계: `autoActions`를 켜요.
  - 마지막: Slack을 켜요.
- **`autoActions` 켜는 조건**(기준값은 회사 확인)
  - A1 시험표를 전부 통과해요(금지 문장 오실행 0건).
  - 파일럿 첫 주에는 꺼 둬요.
  - `cancel-auto-10m`이 10% 이하일 때 켜요. 표본은 10명 이상이어야 해요.
- **실제 연결 순서**(기획 권고): IdP(로그인·명단·층·역할 그룹) → 실제 분장표 → 공지 사본 → 카탈로그 → 회의실 장부(읽기부터) → 근태(등급 2) → 캘린더·Slack
- **파일럿 규모 가정**: 층 1~2개, 직원 50~150명, 동시 사용자 10~30명이에요. 서버 한 대 + PostgreSQL 한 대 + 백업이에요.
- **CI 환경**: GitHub 호스트 러너 + `services: postgres:17`을 써요. 가상 자료와 FakeProvider라 비밀이 필요 없어요. 사내 러너는 실제 IdP·그룹웨어 계약 시험을 붙일 때만 필요해요.
- **문구**(UX 제안, 화면설계 "보안이 보이는 문구" 표에 더할 후보)
  - IdP 장애: "지금 회사 로그인을 확인하지 못했어요. 잠시 뒤에 다시 해 주세요. 계속 안 되면 IT 창구에 알려 주세요"
    - 401이 아니라 503으로 보내요. 401이면 로그인 화면으로 넘어가서 쓰던 글이 사라져요.
  - 배포 뒤 다시 로그인: "앱이 새로 바뀌어서 다시 로그인해 주세요. 쓰던 글은 저장하지 않아서 다시 써 주세요"
    - 새 화면 묶음이 나와도 자동으로 새로 고치지 않아요. "새 버전이 있어요 [새로 고침]" 띠만 보여 줘요.
  - 올리기 확정 카드 꼬리: "올린 품목은 7일 동안 판에 있어요. 내 이름은 안 보여요"
- **기기 비율(PC·폰)**: 10일 차 측정(오프라인 골든셋)에서는 나오지 않아요. C3 집계에 "폰/PC" 두 값만 일별로 세요. UA 원문과 가명 ID는 남기지 않아요.
